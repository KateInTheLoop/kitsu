- Epic/story/card: E03 / E03-S04 / E03-S04-C2
- Requirement: let the read-only recovery planner derive exact ancestry when a
  selected canonical payload is missing or digest-broken, without trusting that
  payload or weakening ordinary lookup. Split physical HEAD/manifest verification
  from payload verification; only a descriptor-pinned, HEAD/child-digest-bound
  manifest may supply a parent link. Unverified and future manifests must stop.
- Evidence and expected failure: the requirements-first selected missing/tamper
  fixture failed to compile because `PhysicalFileStoreV1` had no
  `read_head_envelope`; physical HEAD reading verified canonical bytes before it
  could return the independently bound manifest. After the first implementation,
  review added unreadable-intermediate, manifest-retarget, and future-parent
  cases, exposing and then pinning the trust boundary.
- In scope: a private verified manifest envelope retaining its pinned revision
  directory; a HEAD-bound envelope read; explicit payload-upgrade verification;
  unchanged full `read_head`; selected and intermediate missing/digest-broken
  payload recovery planning; manifest digest and future logical ancestry refusal;
  cross-store envelope rejection; no-mutation assertions. Out of scope: typed
  skipped/blocker evidence, recovery revision assembly/publication, quarantine
  lifecycle, production mounting, branch/fork/export, second-store conformance,
  and X005 promotion.
- Authority/failure/version/rollback notes: the envelope proves only physical
  store/session/revision identity, manifest schema/shape, and exact manifest
  digest binding; it carries no canonical bytes or decoded value. Payload is
  trusted only after separate regular-file, bounded-length, and SHA-256 checks.
  A future physical manifest cannot form an envelope; a future logical manifest
  cannot be crossed. Reads grant no authority, HEAD is never rewritten, and
  current-v1 production files remain exact rollback.
- Tests added or changed:
  - missing and digest-broken selected B preserve ordinary typed corruption but
    expose the exact HEAD-bound B→A manifest link and plan only verified A;
  - digest-broken selected C and intermediate B cross both captured manifest
    links and select only fully verified A;
  - a self-consistently edited selected B manifest is no longer HEAD-bound, so
    planning stays unavailable despite valid A;
  - corrupt selected C cannot cross a future-logical B manifest to valid A;
  - the existing nine-case physical HEAD/revision table still preserves exact
    unavailable state for faults that cannot yield a trusted recovery path;
  - every successful or unavailable plan leaves ordinary lookup and selected
    HEAD evidence unchanged.
- Implementation: refactor physical revision open into two stages.
  `open_revision_envelope` verifies and captures the descriptor-pinned manifest;
  `verify_revision_candidate` upgrades that exact envelope only after validating
  canonical content. `read_head_envelope` binds HEAD to the captured manifest,
  while existing `read_head` composes both stages and preserves full-read
  semantics. Recovery uses envelope links at every step, checks current logical
  schema before crossing, and decodes/artifact-verifies only a candidate that
  passes the payload upgrade.
- Review findings and fixes: review added two-generation physical corruption to
  rule out a selected-only special case, manifest retargeting to prove the
  envelope is not a manifest scan, and a future intermediate schema to prevent
  downgrade through unknown ancestry. The payload upgrade now rejects an
  envelope from another physical store. A test initially retained the first
  writer fence while acquiring the second; review corrected the fixture to drop
  the completed fence rather than weaken writer exclusion.
