# E11 / T0-S2 — the TUI crate and its terminal lifecycle

- **UTC start/end:** 2026-10-13T19:37Z / 2026-10-13T20:21Z
- **Branch/base:** `features/tui_herdr_improvements` / `7f3133c`
- **Epic/story/card:** E11 / T0-S2, one card. Nothing is drawn yet.
- **Requirement:** N5 and N6. Giving the terminal back on every exit path has
  to be right **before** anything is drawn on it, and the project already
  carries a known wart where `kill -9` mid-turn leaves the terminal raw. This
  card adds no new such path.

- **Evidence and expected failure:** 12 tests written first against an absent
  type. `error[E0433]: failed to resolve: use of undeclared type 'TuiRuntime'`
  repeated per use site, plus the same for `sanitize_title` and
  `install_panic_restore`.

- **In scope:** the crate, its pins, `TuiRuntime` enter/leave/Drop, title
  sanitisation, and the chained panic restore.
- **Out of scope:** every widget, the viewport, the event loop, the `Surface`
  seam, and the bridge — `kitsu-tui` is deliberately **not** a dependency of
  `crates/kitsu` yet.

- **Two gate corrections, both evidence-backed:**
  1. **The MSRV gate the plan specified is impossible** and always was. The
     workspace declares `rust-version = "1.80"`, but `clap 4.6`, `zeroize 1.9`,
     `indexmap 2.14`, `time 0.3.55` and others were already pinned at releases
     whose manifests declare edition 2024, which Cargo 1.80 cannot parse at
     all. Recorded as **F9**; the plan's gate text is corrected in four places
     in this commit. The honest replacement, which this card did meet: every
     newly added dependency's own `rust-version` is no newer than the existing
     floor — ratatui 0.29 needs 1.74, crossterm 0.28 needs 1.63, vt100 0.15
     declares none — so this card moves the floor neither way.
  2. **`vt100 = "0.16"` is unusable here**, which the test author found: it
     needs `unicode-width ^0.2.1` while ratatui 0.29 pins `unicode-width
     =0.2.0` exactly, and the resolver refuses. `vt100 = "0.15"` resolves
     0.15.2 with the same `Parser` and `screen` API the tests use. The plan is
     corrected.

- **Tests added or changed:** 12 added, none changed. The writer is generic
  specifically so the lifecycle is testable against a buffer, and the tests use
  a shared sink built on `Rc<RefCell<Vec<u8>>>` so the bytes written by `Drop`
  are readable after the runtime has gone out of scope. Highlights:
  - **The card's named test**: `leave` called twice emits the restore bytes
    exactly once, counted by occurrence rather than asserted as a prefix.
  - Restoration proven on all four paths: explicit `leave`, repeated `leave`,
    `Drop` after `enter`, and `Drop` after an explicit `leave` adding nothing;
    plus `Drop` without `enter` writing nothing at all.
  - `enter` returns `Ok` on a non-terminal, which every test, pipe and
    scripted run is. Erroring there would have made the type untestable and
    the piped path fragile.
  - A hostile title (`"x\x1b\\\x1b]0;pwned\x07"`) is rendered inert, and the
    sanitised payload wrapped in its OSC contains exactly two escape bytes —
    the opening and the terminator — so it provably cannot break out. **This
    is a security property**, because the title will carry agent counts and
    state derived from activity labels that model-driven work influences.
  - The complete enter-plus-leave stream is fed through a terminal emulator
    and asserted to print **no visible text**, which proves the bytes are
    well-formed control sequences rather than merely equal to a literal.
  - The panic restore chains rather than replaces, verified by installing a
    flag-setting hook, panicking inside `catch_unwind`, and asserting the flag
    — with the previous hook saved and restored, since the hook is
    process-global.

- **Three things the test author raised and the implementer handled:**
  1. `enter` sanitises its **own** argument rather than trusting the caller.
     Defence in depth that costs nothing, since this is the boundary where
     model-influenced text could otherwise reach a terminal as control codes.
  2. `leave` performs I/O but returns `()`, so a failed restore is invisible.
     That is correct for a `Drop` body — a destructor must not panic or
     propagate — and there is nothing useful to do about a terminal that will
     not accept its own escape sequences. The swallowing is commented at every
     site so it reads as deliberate.
  3. **Title save and restore silently does nothing under tmux and GNU
     screen**, which is exactly where agent-herding sessions live. An ignored
     sequence is inert, not broken, but the restore is a no-op there. There is
     no portable alternative, because OSC 2 has no query form so the old title
     cannot be read back. The crate documents this plainly, names both
     multiplexers, and notes that setting the tmux *pane* title when `$TMUX`
     is set is a possible later addition. The bytes were deliberately not
     changed.
