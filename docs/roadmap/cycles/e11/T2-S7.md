- **Epic/story/card:** E11 / T2-S7 — the last story of milestone **T2**.
- **Requirement:** **N8** (as amended by T2-S6). Records **F44**, **F45**,
  **F46**, and answers F40's two open candidates.

- **What shipped.** A parked background agent is now visible to tools *outside*
  the process: the state file reports process state `blocked`, `counts.blocked`
  and a per-agent `waiting_for`; `[hooks] on_agent_state` fires
  `STATE=blocked` with the same value; and `kitsu agents --json` reports both.
  **Milestone T2 is complete** — an agent can park on a permission, be seen
  inside and outside kitsu, be answered from anywhere, be recorded, and cannot
  hang.

- **This card's exposure was the worst in the milestone, and the reason is
  structural (F44).** A hook runs an **external program** and the state file is
  read by other tools, so anything reaching them has left the process — unlike
  T2-S6, where a leak would at least have stayed in kitsu's own output.

  F40 named two candidates; both were read, and the answers differ:
  - **The hook payload assembly was never narrow.** Its `waiting_for` was
    already a **free-form `String`**, protected only by `safe_inline_label`
    (bounding, whitespace collapsing, and the credential-shaped redactor that
    leaves paths untouched). An argument could have reached an external program
    **with no type change, no signature change and no public API change at
    all** — the natural phrase *"waiting for permission to write
    /work/notes.txt"* would have required changing nothing, and nothing
    downstream would have caught it. The label is argument-free today only
    because every call site happens to format a tool *name*. That is F40's
    accidental protection, one layer further out.
  - **The state-file writer is a narrow struct wrapped around a wide one.** Its
    own fields are safe, but it embeds the full thread snapshot with its
    free-form `task`, `model` and timeline texts. What protects it is one layer
    down, and it is **T2-S6's structural guarantee**, not the wrapper and not
    `validate`, which runs the same credential-shaped redactor.

  **Mitigated structurally rather than by care:** the blocked reason travels as
  `Option<AgentApprovalKind>` — a **unit enum** — on both `AgentProgress` and
  the snapshot DTO, so it reaches the assembly sites in a type that *cannot
  hold an argument*, and the hook only calls `.wire()`. Produced once, at the
  pre-existing `approval_kind` boundary; the payload never travels further.

- **One machine vocabulary, one human vocabulary (F45).** The three machine
  surfaces did **not** agree, and the divergence was invisible because only one
  of them had the field at all. Left alone the natural implementations would
  have split — snake_case serde on one side, the English `label()` on the other
  — and the mismatch would have been found by whoever first wrote a tool against
  both. Resolved and approved at review: `wire()` → `read_file` / `write_file`
  / `run_command` is the single machine vocabulary for the state file, the hook
  environment and `kitsu agents --json`; `label()` keeps the human phrasing
  `/jobs` prints. A test asserts the DTO spelling **is** `wire()`, so a second
  machine vocabulary cannot appear later.

- **A real defect fixed, found by the tests.** A parked agent's
  `KITSU_AGENT_WAITING_FOR` reported the stale activity label **`"started"`** —
  the hook correctly said `blocked` and then gave a nonsense reason, because
  `park_prompt` records no telemetry activity. The tempting fix — calling
  `record_activity` with the request — **is the leak path**; the reason travels
  as the typed kind instead, and the activity label is still used for agents that
  are merely running.

- **The gap I asked to be closed, and what closing it proved.** The test author
  flagged honestly that `kitsu agents --json` had **no failing-first test**,
  because it is a pure reader whose bytes are the state file's. Rather than
  accept that, I asked for the plan row's end-to-end acceptance — and it was far
  cheaper than estimated, because T2-S5a's pseudo-terminal driver already parks
  a real agent.

  The result is the only test in this milestone that proves the surfaces work in
  a **real process**: a live state file on disk read while the agent is parked,
  and `kitsu agents --json` run as a **separate child** against that same file.
  Its best assertion compares **the two machine surfaces against each other**
  rather than each against a constant — which is precisely the F45 defect no
  per-surface test could catch.

  It also corrected my brief: the gated fixture is a **read**, so the published
  kind is `read_file`, not `write_file`. Both kinds are now covered — one
  end-to-end, one in units.

- **Non-vacuity proven by mutation, including one case that needed two.** The
  feature was removed one line at a time and the test watched to fail. Steps 2-4
  turned out to be defended **twice** for a released agent (`unblock()` clears
  the field *and* `snapshot()` gates on the phase), so removing either alone
  left the test green; both had to go before it failed — showing a poller being
  told a *finished* agent still waited on a permission. The author used exact
  string replacement with exact inverses and **md5-verified** the file
  afterwards, explicitly avoiding `git checkout` (**F42** — my mistake, now a
  rule others are following).

- **F46, a new harness rule in the opposite direction from F37's.** T2-S5a
  taught "poll `/jobs view`, never bare `/jobs`". This card's first run proved
  the mirror image: after a reply, the completion signal reaches the transcript
  **only through the deck**, because `/jobs view` never prints a finished
  agent's result. Polling `/jobs view` alone made it unreachable and the test
  died on the deadline. Both halves are now recorded, with the general lesson:
  **a PTY test that times out is almost never a timing problem — it is usually
  watching a view that cannot print what it waits for.** Raising the timeout
  would have hidden all three instances.

- **New test infrastructure, reviewed:** `run_plain_interactive_chat_pty_with_env`
  takes per-child environment so the carrier's state file lands in a **private**
  `XDG_RUNTIME_DIR`; the existing function delegates to it with an empty slice,
  so no call site or assertion changed. This matters for isolation rather than
  convenience — setting `XDG_RUNTIME_DIR` on the parent would break the rule
  every other state-file test follows *and* let a stray kitsu on the machine
  pollute the listing. The reader helper asserts it finds **at most one**
  `<pid>.json`, so a second publisher is a failure rather than a silent pick.
