# E11 / T1-S6 — the agent state-transition hook (completes milestone T1)

- **UTC start/end:** 2026-10-13T18:37Z / 2026-10-13T19:24Z
- **Branch/base:** `features/tui_herdr_improvements` / `0661b9b`
- **Epic/story/card:** E11 / T1-S6, one card. **Milestone T1 completes here.**
- **Requirement:** H3 and N7. The state file lets an outside tool poll; this is
  the push counterpart, so a herder learns about a transition when it happens
  rather than on its next sweep.

- **Three decisions I settled and recorded in H3 before implementation**,
  because the requirement's original wording left them open and each is
  user-visible:
  1. **Exact variable names** `KITSU_AGENT_ID`, `KITSU_AGENT_STATE`,
     `KITSU_AGENT_WAITING_FOR`. The original `KITSU_AGENT_ID/STATE/WAITING_FOR`
     shorthand was ambiguous about whether the prefix repeated.
  2. **No shell.** The configured string is split into argv and executed
     directly with no expansion, so a stray metacharacter in a config file
     cannot become execution and behaviour does not depend on which shell is
     installed. A user wanting interpolation points this at a script or writes
     `sh -c` themselves — explicitly theirs rather than kitsu's default.
  3. **Output discarded, never awaited.** All three descriptors are null,
     because a hook writing to stderr would splice into the live status row and
     break the byte-identical guarantee N1 gives plain, non-TTY and assistive
     output. This is the single most important property in the card: it is a
     correctness constraint on kitsu's own rendering, not hook hygiene.

- **Evidence and expected failure:** 24 tests written first — 19 in the new
  module, 5 on config. Observed E0425/E0422 for `AgentObservation`,
  `HookEvent`, `split_command`, `agent_state_label`, `transitions`,
  `hook_env` and `fire`, plus config failures on the missing `hooks` field.
  The author verified satisfiability with a stub (676 passing) and reverted it.

- **In scope:** the splitter, the labels, transition detection, the
  environment, the runner, the config table, the wiring, and documentation.
- **Out of scope:** mid-turn reactivity (the same deferred watcher card as the
  state file), and any hook other than `on_agent_state`.

- **Authority/failure/version/rollback notes:** runs a command the user put in
  their own config, at their own privilege — the same trust level as a shell
  alias, and no model input chooses it. The one place agent-influenced text
  crosses the boundary is `KITSU_AGENT_WAITING_FOR`, derived from activity
  labels, so it is bounded and stripped of control characters and NUL before
  it reaches the child. No network (N7) — the feature is an exec. Rollback is
  removing the config key; absent or unsplittable means no hook.

- **Tests added or changed:** 24 added, none changed. Highlights:
  - The splitter is proven to perform **no** expansion: `$HOME` survives as
    literal characters and `;`, `|`, `&&`, backticks, `$(…)` and `*` all come
    through as ordinary argument bytes. That is what makes the no-shell
    contract observable rather than merely claimed.
  - A test asserts the hook's state word is byte-identical to what `/jobs`
    prints for the same status, so one agent can never be described by two
    vocabularies.
  - **The re-fire guard has its own test**: comparing an observation set with
    itself fires nothing. These functions run at every turn boundary, so
    "once per transition, never once per observation" is the property that
    decides whether the feature is usable or a notification storm.
  - The nulled-stdio guarantee is asserted **from inside the child**: the
    script duplicates its three descriptors before its own redirect, then
    reports what they point at, and the assertion is `/dev/null` three times.
    A unit test cannot redirect the harness's own descriptors, so this was the
    way to test it rather than assume it — and the author reported it caught a
    real bug in its own first attempt, where the redirect preceded the
    readlink.

- **Implementation:** `agent_state_label` delegates straight to
  `agent_progress_status_label` rather than restating a match, so the
  byte-equality with `/jobs` is structural and cannot drift. `transitions`
  builds a map of previous states and keeps only entries that are new or
  changed, so a vanished id is never iterated and therefore cannot fire.
  `fire` spawns with all three descriptors null and `kill_on_drop`, then hands
  the wait to a detached task under a ten-second timeout: the caller's only
  synchronous work is the spawn, the child is reaped rather than left a zombie,
  and a spawn error, nonzero exit or timeout is discarded.

- **Review findings and fixes:**
  1. **A trap the test author found and passed on, which would have shipped a
     lie.** `safe_inline_label("")` returns the word `"unknown"`, not an empty
     string — I verified this in `subagent/thread.rs`. Routing an absent
     `waiting_for` through the sanitizer would therefore have exported
     `KITSU_AGENT_WAITING_FOR=unknown`, telling a hook that the agent was
     waiting on something named "unknown". Both the transition builder and the
     environment builder now bypass the sanitizer for an empty value, with
     comments naming the reason, and tests pin it.
  2. The author also pre-diagnosed the runner's shape from its own stub: a
     plain synchronous spawn with no wait leaves a zombie until kitsu exits,
     while a blocking wait fails the non-blocking test. Passing that on saved
     the implementer the rediscovery.
  3. Verified by reading rather than by report: zero `eprintln!`/`println!`
     and zero `unwrap`/`expect`/`panic!` in the module's production half, all
     three descriptors nulled, and the hook gated on a usable command alone so
     it works with `[agents] state_file = "off"` — they are independent
     features and a user may want one without the other.

- **Commit:** see below.
- **Residual risk:** hooks fire at turn boundaries, so a transition during a
  long turn is reported when the turn ends, not when it happens — the same
  cadence caveat as the state file, documented rather than implied. The ten
  second bound is fixed rather than configurable. And because the command runs
  at the user's own privilege with no sandbox, a careless config is a foot-gun;
  the documentation says plainly that it is executed directly.

  library crate because `kitsu` is binary-only and a future `kitsu-tui` cannot
  import from it.
