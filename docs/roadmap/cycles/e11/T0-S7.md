# E11 / T0-S7 — Ctrl+Z suspends without handing back a broken terminal

- **UTC start/end:** 2026-10-14T00:18Z / 2026-10-14T01:26Z
- **Branch/base:** `features/tui_herdr_improvements` / `fabbee3`
- **Epic/story/card:** E11 / T0-S7. A card added after T0-S6, not in the
  original plan: it clears **F21**, one of the two regressions the go/no-go
  record named as blocking inline mode from ever becoming a default.
- **Requirement:** R3. Resolves **F21**; records **F22**.

- **Why this before F20.** The go/no-go named two blockers. F20 (the
  slash-command palette, completion, cross-session history) drags the multi-row
  composer in with it and interacts with F16 and F19 — milestone-sized. F21 is
  one card, and left alone it is actively user-hostile rather than merely
  missing: the naive version of Ctrl+Z stops the process with the scroll region
  still set, handing the shell a terminal whose scrolling area is a subset of
  the screen.

- **The editor already did its part.** `EditorAction::Suspend` has been emitted
  for `0x1a` since the keymap was extracted; the reader was simply swallowing
  it alongside Tab and Ctrl+backslash. So no change to `kitsu-editor` at all —
  the test author checked that before accepting the card's scope, which is the
  right order to find it out.

- **What shipped.** The reader returns `Suspended(draft)` **at the keystroke**,
  carrying the draft and leaving the signal and the terminal to the caller — a
  test feeds bytes after the Ctrl+Z and requires they belong to the *resumed*
  read rather than this one. The caller releases the viewport, restores terminal
  modes, stops, re-engages, reinstalls, and re-enters the reader with the
  preserved draft through the same replay path that already carries a draft
  between prompts, so **typing survives a suspend/resume cycle**.

- **The ordering is the correctness property, and it is now pinned.** The region
  must be gone and the terminal canonical *before* the process stops, because a
  stopped process cannot clean up after itself and the stop is a blocking call —
  no later code can rescue a wrong order. The test author pointed out that unit
  tests could not reach this and **declined to invent a seam from a test card**,
  which was the right call: it would have pre-empted a production-design
  decision. I authorised the seam (`SuspendEffects` / `suspend_and_resume`) and
  the implementer built it.

- **Review findings and fixes:**
  1. **The implementer flagged that the seam had no test using it** — eleven new
     tests and not one constructed a `SuspendEffects`, so the call order was
     pinned only by review. That made the seam pure indirection: structure with
     no benefit, which is worse than no seam. **The gap was mine** for
     authorising it mid-card without extending the test brief. Closed as
     reviewer with two tests and a recording fake, and **verified by mutation**:
     moving the stop ahead of the release turns the test red, so it catches the
     mutation that actually matters rather than merely passing.
  2. Accepted the implementer's choice to make the unreachable `Suspended` arm
     in the outcome mapper fall through quietly rather than `unreachable!()`, so
     a future refactor cannot turn it into a panic at an idle prompt. That is
     the right instinct for a path a user sits on.
  3. Verified by reading rather than report: no escape sequence is written
     anywhere in `tui_bridge.rs` — release and reinstall delegate to
     `InlineSurface`, which stays the only place the byte sequences live. That
     is why the round-trip test comparing against a second, independently
     installed guard holds by construction rather than coincidence.

- **Ctrl+backslash stays inert, deliberately.** The conventional action
  re-raises `SIGQUIT`, whose default disposition terminates **and dumps core**.
  This process holds API tokens and conversation text in memory, so honouring
  the convention would write credentials and user content to disk because of one
  mistyped keystroke. A passing test pins the inertness so it reads as a
  decision rather than a gap. If revisited, the right shape is to disable core
  dumps (`RLIMIT_CORE`) *and then* honour the signal.

- **Acceptance commands/results:**
  ```
  cargo test -p kitsu --bins / --release    670 passed each  (657 + 11 + 2)
  cargo test -p kitsu --test tui             6 passed        (unchanged)
  cargo test -p kitsu --test cli           229 passed        (unchanged)
  cargo test -p kitsu-tui / -p kitsu-render 33 / 112         (unchanged)
  cargo clippy --workspace --all-targets      0 warnings
  cargo fmt -p kitsu -- --check               clean
  ```
  Nothing hung: the stop signal is raised only by the real caller-side
  implementation in `main.rs`, which no test constructs — a unit test that
  raised it would stop the test binary rather than fail it.

- **Documentation (standing requirement, in this commit):** three surfaces I
  wrote one card ago listed Ctrl+Z as missing and were now wrong — `README.md`,
  `CHANGELOG.md` and `docs/ux-design.md` all corrected, each also recording the
  Ctrl+backslash decision and its reason so the inertness is not read as an
  oversight. `docs/ux-design.md` additionally documents that the ordering is the
  correctness property and is enforced behind a seam. **F21** marked resolved;
  **F22** opened for the missing end-to-end coverage; the terminal matrix gained
  a suspend row, since that is currently the only check of the real cycle.

- **Commit:** see below.
- **Residual risk:** **F22** — no automated test exercises the real cycle. The
  test author probed it rather than guessing: the stop/continue mechanics do
  work in this environment, and the harness tolerates a stopped child but cannot
  *detect* one, because `try_wait` omits `WUNTRACED`. It was deferred for two
  honest reasons — its stability could not be measured before the feature
  existed (the only observable run was a deadline timeout, exactly the shape
  that becomes an intermittent), and building it means changing the harness all
  six pseudo-terminal tests share. Now that the implementation exists it is a
  follow-up card where stability *can* be measured.
- **Next card:** the F22 end-to-end test, or F20 — which is now the last thing
  between the preview and a defaultable renderer, and is milestone-sized.
