# E11 / T0-S17 — the idle prompt ranks its own completions

- **UTC start/end:** 2026-10-14T05:52Z / 2026-10-14T06:25Z
- **Branch/base:** `features/tui_herdr_improvements` / `c1aa851`
- **Epic/story/card:** E11 / T0-S17
- **Requirement:** R4 cleanup. Resolves **F30**; confirms and narrows **F28**.

- **Why this card, immediately after the one that caused it.** T0-S16 shipped a
  stand-down clause that hid a *correct* palette because an *inappropriate* hint
  disagreed with it. I accepted it on the grounds that all tests agreed and the
  behaviour was explainable, and carded the cause. Fixing it while the reasoning
  was still loaded was cheaper than letting it set.

- **The defect was mine, from two earlier cards.** `typeahead_slash_hint` ranks
  through `MID_TURN_HINT_PRIORITY`, whose own doc comment says those commands
  outrank registry order *"while a turn is live"*. T0-S9 and T0-S10 reused it at
  the idle prompt, where no turn runs. **The general lesson, recorded:** reusing
  a function carried its *policy* along with its mechanics, and the policy was
  named for the context it came from — the name said `MID_TURN` and it was
  called where no turn exists.

- **The fix makes the invariant structural.** `idle_slash_hint` ranks by
  registry order; the during-turn row keeps `typeahead_slash_hint`. Both are
  thin wrappers over one `slash_hint_ranked` holding the shared structural
  rules, so only the ranking differs. **The function name is how a call site
  declares its policy** — there is no default left to inherit silently, which is
  precisely what the defect was. The third stand-down clause is gone, and a test
  pins it as *removed* rather than merely unreachable by passing the old
  disagreeing hint explicitly and still requiring a palette.

- **Two call sites, not one — and I checked this independently.** The idle
  prompt reads the hint in `hint_of` (what the row *displays*) **and** in the
  `CompleteRequest` arm (what Tab *accepts*). Both inherited the wrong ranking,
  which means the defect was never cosmetic: **Tab at an idle `/s` typed
  `/steer`**. A fix touching only the display would have left the row showing
  one completion while the key inserted another — worse than the bug. I verified
  both sites before briefing and the test author found the same pair
  independently.

- **The property test found a second defect neither I nor T0-S16 noticed.** Its
  invariant — *for any slash prefix with a match, `prefix + hint` equals the
  lead palette entry's name* — failed first on **`/agent`**, not `/s`. The
  during-turn selector tests `name.len() > rest.len()` as part of *choosing* the
  match, so it steps over an exact match: `/agent` hinted `s`, completing
  `agents`, while the lead is `agent` itself. Fixed structurally by moving the
  length test out of the ranking into the shared tail, so an exact match empties
  the hint rather than sliding to a longer sibling — **no command name is
  special-cased**, verified.

  **The lesson is about the instrument.** Example-based tests had covered this
  area for three cards (`/s`, `/co`, `/cont`, `/context`, `/mod`) and none
  happened to be a command name that is also a prefix of another. A property
  over all ~390 prefixes found it on the first run.

- **Review findings and fixes:**
  1. **The implementer escalated a blocker instead of working around it, and it
     was right to.** Four pre-existing tests pinned the old behaviour at exactly
     the rewired call sites — one of them stating in its own prose *"Tab at an
     idle `/s` types `/steer`"*, which is F30's symptom written down as an
     expectation. No implementation could satisfy both. The test author had
     updated one regression net and missed this group. I made the change,
     keeping `/s` as the input so the tests assert the corrected behaviour
     rather than dodging the interesting case, and the cursor column moved with
     the shorter word. Two sibling doc comments still named the during-turn
     function as the inline reader's; corrected.
  2. Accepted keeping the now-unused `hint` parameter on
     `slash_palette_adds_to_the_row` as `_hint`: a test deliberately passes the
     old disagreeing hint to prove the clause is gone, so the arity is load-bearing.
  3. The implementer flagged that its card forbade `docs/` and that the standing
     documentation requirement would therefore be unmet at commit time — correct,
     and handled here.

- **F28 confirmed and narrowed, which is the other substantive outcome.** The
  transaction flake I had recorded as "seen once, unreproduced in 13 attempts"
  recurred, and I reproduced it: **1 failure in 12** full-suite runs. Then,
  following that finding's own recommendation: **0 of 15** isolated, **0 of 8**
  with its own module in parallel. So it is **cross-module interference**, not
  an intra-module gap as first guessed, and not an inherently racy test. The
  bisect strategy and the suspect globals are recorded, along with the
  requirement that any fix be verified by a dozen full parallel runs rather than
  an isolated one. A second reported flake did not reproduce and is recorded as
  one sighting rather than given a number.

- **Documentation (standing requirement, in this commit):** `CHANGELOG.md`
  describes the ranking change in user terms — `/s` now suggests `save` and
  opens the palette where it previously suggested `steer` and opened nothing —
  and states that the during-turn row is deliberately unchanged.
  `docs/ux-design.md` drops the third stand-down case, explains why two now
  suffice (the hint, Tab and the lead entry agree by construction), records that
  the two policies are separate named functions so a call site cannot inherit
  the wrong one, and documents the empty-hint-on-exact-match rule with
  `/agent` as the example. No `README.md` change: its description of the
  prompt remains accurate at its level of detail.
