- **Requirement:** A8 of `docs/tui-and-agent-view-design.md`. The ambient
  `← N agents` indicator must be drivable from the registry `watch` channel.
  `AgentRegistrySnapshot` carried only `generation/running/terminal/failed`,
  none of which answers "is there a result waiting for me" — `terminal` stays
  set forever once an agent finishes. Add `unacknowledged` (terminal agents
  whose handoff is still `Ready`) and `blocked` (reserved, always 0 until the
  T2 story introduces a user-answer wait state), so the status row lands in
  T1-S2 and T2 without a second snapshot migration.

- **Evidence and expected failure:** 9 tests written first, against fields
  that did not exist. Expected and observed failure:

  ```
  error[E0609]: no field `unacknowledged` on type `AgentRegistrySnapshot`
      = note: available fields are: `generation`, `running`, `terminal`, `failed`
  error[E0609]: no field `blocked` on type `AgentRegistrySnapshot`
  ```

  20 instances, all E0609, nothing else in the tree red. Note for later
  cards: `kitsu` is a binary-only package, so `cargo test -p kitsu --lib`
  errors with `no library targets found`; the correct invocation is
  `cargo test -p kitsu --bins`.

- **In scope:** the two fields, their population in `changed_snapshot`, the
  four struct literals in the `background_agent_notice` tests, and the tests.
- **Out of scope:** any status-row rendering (T1-S2), any real `blocked`
  state or blocking behavior (T2), any change to notice text or to
  `AgentProgressStatus` / `AgentThreadPhase` (T2-S3).

- **Authority/failure/version/rollback notes:** no authority surface touched;
  no permission, provider, or session path involved. `handoff()` is a pure
  read, so no new instance of the documented release-profile hazard where
  `acknowledge_handoff()` must never be called inside `debug_assert!`
  (guarded by the existing `acknowledgement_transition_survives_the_release_profile`).
  No schema or wire version changes: `AgentRegistrySnapshot` is in-process
  only and is not serialized. Rollback is deletion of the two fields; nothing
  reads them yet.

- **Tests added or changed:** 9 added to `mod tests` in
  `crates/kitsu/src/subagent.rs`, none changed. Fresh snapshot reads zero;
  a done agent reads `terminal == 1` and `unacknowledged == 1`;
  acknowledging publishes a strictly greater generation with
  `unacknowledged == 0` and `terminal` still 1; `result()` clears the count
  while `peek_result()` does not; a failed agent is unacknowledged until
  acknowledged, so `failed` and `unacknowledged` are independent; draining
  unobserved results clears it; one of two acknowledged leaves one;
  `close`/`prune` leave no stale count; and a guard test pins `blocked` at 0
  with a comment telling T2 to update it deliberately.
  The four existing `AgentRegistrySnapshot` literals in `main.rs` tests
  gained `unacknowledged: 0, blocked: 0`; no assertion was altered.

- **Implementation:** two documented `usize` fields after `failed`, and one
  `filter(handoff() == Ready).count()` fold in `changed_snapshot`, which
  already runs under the `agents` lock. Counting `Ready` is the whole
  definition of "terminal and unobserved": `thread.rs` sets `Ready` only
  inside `finish`, which early-returns unless the phase is currently
  `Running` and refuses a non-terminal new phase, so `Ready` strictly implies
  terminal. `blocked` is a literal 0.

- **Review findings and fixes:**
  1. The implementer refused to run `cargo fmt` because it would have edited
     test code, which its brief forbade. Correct call. Reviewer applied
     `cargo fmt -p kitsu` instead, scoped to this package so the pre-existing
     `kitsu-tools` debt stayed untouched; verified the change is pure
     re-wrapping of three `assert_eq!` calls with identical arguments.
  2. `unacknowledged` was verified against the code rather than the report:
     `take_unobserved_terminal_results`, `result()` and `acknowledge_result`
     all call `acknowledge_handoff()` outside `debug_assert!` and before
     `changed_snapshot`, so the published count is correct in each path, and
     `peek_result` correctly does not acknowledge.
  3. The implementation is broader than its tests: `Ready` also covers
     `Cancelled`, which the test author skipped because reaching it needs an
     async cancel with an attached task. Accepted as an invariant-backed
     gap; `agent_cancel_is_idempotent_and_prunes` is the hook if a later card
     wants it asserted.
  4. Deliberate non-change: three separate `filter().count()` passes over a
     small locked map rather than one merged fold, to avoid rewriting the two
     existing unrelated passes.
