- **What shipped.** The agent view overlay: opened by `Ctrl+X a` (reading
  `[tui] prefix`), by `/jobs view` or `/agents view` in a TUI mode, or by
  pressing `←` twice on an empty composer; grouped by state with agents needing
  input first; `?` for keys, `Esc` to close and restore.

- **This card connected three things deliberately left unreachable.** T4-S1's
  model had no renderer. `[tui] prefix` and `[tui] left_arrow_opens_agents` had
  been **bound since T3-S2 purely so they were not silently unreachable**, with
  no consumer — this card is their first. And the DTO→row mapping's dead-code
  marker named T4-S2 as the caller that would arrive; two markers were dropped.

- **A1 was factually stale on two clauses, both describing work already
  shipped.** It said the `/agents` alias "today forwards only an empty or
  numeric argument" and that the mid-turn handler "gains the same subcommands".
  I verified both false: the alias forwards everything else **verbatim**, with a
  comment saying `/jobs` owns the suggester, and the mid-turn handler already
  had all three. **The widening was a no-op**, so dispatch was not restructured
  and one of the overlay tests passed with no dispatch change at all. That is the
  eighth time in this epic a plan or requirement described existing work.

- **The part I held acceptance for: how `↑` is protected.** History recall
  breaks loudly, and the new `←` route sits right beside it.

  The arming state is **one local in the inline reader** — not an editor action,
  not derived from the editor's empty-buffer predicate — and
  **`crates/kitsu-editor` is absent from the diff entirely**, which I verified.
  So `RecallRequest` and the deliberate decline that makes `↑` walk history are
  byte-for-byte unchanged rather than merely still passing.

  A byte filter between the read and the editor recognises **five** patterns —
  the prefix byte, `ESC[D`, and the two bracketed-paste delimiters — and
  forwards everything else, so the editor remains the only keymap. It tracks the
  paste delimiters for a specific reason: **inside a paste the payload is text**,
  so a `0x18` or an `ESC[D` in pasted content must arrive as content and not as
  a chord. And a sequence split across two reads is held and released in front
  of the next chunk, so the editor sees the same byte stream either way.

- **Three behaviours A1 did not specify, decided with reasons (F63).** Any
  keystroke other than `←` **disarms** the first press — arming until the view
  opens would make a keystroke's meaning depend on something the user did
  minutes ago and can no longer see. A `←` or prefix byte **inside pasted text
  is content**. And an unrecognisable prefix spelling yields **no chord route at
  all** rather than falling back to the default, because a silent rebinding is
  worse than a chord that does nothing — the user cannot tell their config was
  rejected.

- **The alternate screen was chosen to make an assertion true by
  construction**, which is worth noting as a technique: the transcript stays on
  the primary screen, so the restore is **the terminal's** and the closed screen
  equals the pre-open screen row for row, while the open screen necessarily
  differs. The region reinstatement writes only scroll-region control bytes and
  the pinned row — nothing inside the compared region — so a terminal keeping
  per-screen margins still gets its region back.

- **Craft worth recording.** The implementer **removed a glyph it had first
  written** — a `·` separator — in favour of spaces, with the reason in a
  comment: `deck_marker` has a stable ASCII tier and a separator invented in the
  overlay would not. That is the three-tier discipline applied unprompted. Row
  markers come **only** from `deck_marker(row.state.deck_state())`, so the
  previous card's blocked marker is what a parked agent shows here, and no glyph
  was introduced.

  It also kept the routes-off reader entry point behind a dead-code marker **so
  the reader's thirty existing unit tests keep measuring the editor's keymap and
  nothing this card added** — which is why none of them needed touching.

- **Neither chrome literal moved.** The test author pinned exactly two — the
  overlay's `agent view` token and the hint containing `again` and `agent` —
  because inventing expectations for undrawn chrome is what **F58** punished.
  Everything else is new and the implementer's.

- **F62: `alternate_screen` is now the last key with no consumer**, because the
  overlay takes the alternate screen unconditionally. Accepted, with the reason
  recorded: the in-viewport path's restore would have to come from the **cell
  ring**, which nothing feeds until R6. So `never` depends on a reader that does
  not exist, making it T5 work rather than a small follow-up. Three cards have
  now bound keys "so they are not silently unreachable" and left them inert —
  a pattern worth watching, because a validated key that changes nothing looks
  broken from the user's side.
