- **The agent declined my framing, and was right.** I suggested the enum might
  have to live in `kitsu-tui` with `kitsu` mapping onto it. It showed the
  better home is **`kitsu-render`**: `DeckState` is already there and the new
  enum is a **refinement** of it (four glyph levels to six groups), closing

  `kitsu-core`, which depends on the renderer but not the viewport crate. Its
  words: *"I did not have to accept the weaker answer."*

- **The order cannot fork, and the anti-fork test is the good kind.** `rank()`
  is read **out of** `order()` by `position()` rather than restated, so a
  consumer cannot derive a different order from the same type. And the test
  calls the **real** `jobs_view_group` for all six reachable cases, looks each
  returned heading up in `format_jobs_view`'s **own** array, and asserts that
  index equals `rank()` — with every heading required exactly once so a reorder
  cannot hide in an uncovered arm. `/jobs view`'s wording is untouched; the
  labels differ deliberately and only the groups and their order agree.

- **Two requirement conflicts, both verified by me before accepting the fix.**

  **A2 lists row fields the data cannot supply.** The thread snapshot carries
  **neither** tokens nor last activity — they live on the telemetry, reached
  through a type the snapshot deliberately does not embed. So the plan row's
  "map the snapshot to a row" cannot populate every field A2 names. The pinned
  answer is **`None`, never a zero**, because a zero reads as "no tokens used"
  rather than "not known here" — a confident wrong number is worse than an
  absent one in a view whose job is telling you which agent needs you.

  **A3 never defines its own `o:` key.** It appears once, undefined. Pinned as
  the task/objective substring against `n:`'s name, each confined to its own
  field and asserted in **both** directions. Three further gaps decided and
  pinned: the `s:` vocabulary, that bare unkeyed text is an error, and that a
  repeated key is an error rather than last-wins.

- **Malformed filters are errors, for a reason specific to this surface.** A
  silently dropped term shows the **wrong agents**, and here that means failing
  to show the one waiting on an answer. Five shapes rejected by name, with the
  same test asserting all six state spellings **are** accepted so "rejects
  everything" cannot pass.

- **F61 — the implementer STOPPED on a test that contradicted an invariant, and
  that is why this cost one review instead of a loosened guarantee.** The test
  tabulated all fifteen `(phase, handoff)` pairs and asserted a fixture DTO
  **validates** for each. But the DTO requires `terminal == closed`, a handoff
  **iff** terminal, and no open steering once terminal — so only **eight** are
  representable. And an existing green test pins exactly that: *"a blocked
  thread has no handoff"*.

  **Two specifications demanded opposite things of one function.** The
  implementer named the conflicting test, said the fix belonged in the test
  rather than the invariant, and stopped. Forbidding test edits is what made the
  conflict **visible** instead of silently resolved in the product.

  **My fix is narrower than shrinking the table**, because two properties were
  tangled: the classifier is a **total function over two enums** and asserting
  all fifteen is correct, while the DTO forbids seven. So the classifier keeps
  its fifteen and only the fixture validity and row mapping are confined to the
  eight — with the count asserted, so the guard cannot silently skip everything,
  and a second assertion that those eight still reach **all six** groups through
  a DTO the validator accepts.

  **The fixture was independently wrong**: it hard-coded an open timeline and
  open steering, so it was only valid for non-terminal phases. It now derives
  both from the phase. That is the deeper bug — a fixture that cannot represent
  the states its own test enumerates. **I verified the invariant test is still
  green**, so nothing was loosened.

  One number worth recording: the first estimate of representable pairs was
  **eleven**, by counting only non-terminal-with-handoff and missing
  terminal-without-handoff. The real count is **eight**. The count assertion is
  what makes that checkable rather than assumed.
