# E11 / T0-S8 — verifying what the preview actually lacks

- **UTC start/end:** 2026-10-14T00:52Z / 2026-10-14T02:01Z
- **Branch/base:** `features/tui_herdr_improvements` / `516aaa6`
- **Epic/story/card:** E11 / T0-S8. A **verification** card, not a feature one.
- **Requirement:** none new. Corrects **F20**, resolves **F22**, records **F23**.

- **Why this card exists: I published two false claims.** F20 recorded that the
  inline prompt loses cross-session history and reverse search, and I repeated
  both in `README.md`, `CHANGELOG.md`, `docs/ux-design.md`, the T0-S6 go/no-go
  record and a production doc comment. I noticed while picking the next card
  that the inline reader is handed *rustyline's own* history list, which should
  include whatever was loaded from disk — so the claim was probably wrong. **It
  was.** Telling users a feature is missing when it works is a defect in itself,
  and one that costs trust in every other claim in the same list.

  I briefed the verification so it could correct me twice: *"if my correction is
  itself wrong, say so plainly — I would rather be corrected twice than publish
  a second wrong claim."*

- **Cross-session history works.** Inline mode borrows rustyline's persistence
  wholesale while never running its composer: the file loads at startup, the
  inline reader is handed that same list, `add_history_entry` sits on the
  **common path** after the read — outside the match on which reader produced
  the line — and the file saves on exit. Proven with two real sessions sharing
  one `HOME`, the test also reading the history file directly as independent
  evidence the save ran.

  A detail kept because it reads as a bug until explained: the first version of
  that test pressed Up **once** and recalled `/quit`, since the common path
  records `/quit` too. An empty history would have had nothing to paint at all,
  so that failure was itself proof the walk was reading the saved file.

- **Reverse search works; its status line does not.** `TypeaheadEditor`
  resolves search mode entirely internally and emits no action for it, so the
  reader has nothing to swallow — unlike `CompleteRequest`, which it explicitly
  drops. The honest correction is therefore "reverse search works, without its
  status indicator", not "reverse search works".

- **The remaining losses share one cause, so they are one card.** Tab
  completion, the slash-command palette **and** the reverse-search indicator all
  render into the during-turn row's **hint slot**, and the inline paint callback
  is `(draft, cursor)` with nowhere to put a hint. That reframes the blocker
  from "the inline prompt is missing most of what rustyline gave it" to "the
  inline paint seam carries no hint slot" — materially narrower, and one change
  rather than three.

- **F22 closed.** The suspend cycle now has end-to-end coverage, on the second
  attempt rather than the first: both reasons for deferring it had expired —
  the feature existed, so stability could be measured, and the harness was open.
  The test observes from outside that the child really stops, that the region is
  released before the stop and restored after it, and that a carriage return
  written *while the child was stopped* submits the replayed draft. Evidence: 40
  consecutive full-suite runs in debug, 5 in release.

  Two hazards had to be found the hard way, and both generalise: an inherited
  ignored `SIGTSTP` disposition survives fork and exec (a non-interactive shell
  ignores job-control signals in a forked subshell, so the raise became a
  no-op — 5/5 failures under one invocation, 5/5 passes under another), and
  `waitpid` needs `WUNTRACED` to see a stopped child at all.

- **F23: a test I committed two cards ago was failing about 7% of the time.**
  Found here and measured properly — on the *unmodified* baseline, with the new
  work stashed, `inline_mode_echoes_the_idle_draft_in_the_viewport_row` failed
  **2 of 30** full-suite runs. The scripts triggered their first keystroke on
  the banner, which can arrive while the terminal is still canonical with echo
  on; the terminal then echoes the typed text itself *inside* the scroll region,
  which is exactly what that test asserts must not happen. Every script that
  types at the idle prompt now triggers on the bracketed-paste enable sequence,
  which is written immediately after the terminal is reconfigured and is
  therefore proof that raw mode is on. Zero failures in 40 runs after.

  **The lesson generalises and is recorded as such:** a pseudo-terminal test
  must synchronise on evidence that the program has *taken the terminal*, not on
  it having merely printed something — output proves liveness, not readiness.
  And a green suite is not a deterministic suite: this one had been green every
  time I ran it while failing one run in fifteen.
