# E11 / T3-S1 — the harness that could drive a turn, and the bug it found immediately

- **UTC start/end:** 2026-10-14T12:40Z / 2026-10-14T14:06Z
- **Branch/base:** `features/tui_herdr_improvements` / `6e843de`
- **Epic/story/card:** E11 / T3-S1, milestone **T3**'s first story.
- **Requirement:** test infrastructure for all of T3. Records **F47**.

- **What shipped.** `run_styled_streaming_chat_pty`: the existing styled PTY
  harness plus a **dependency-free local SSE server** the child really talks to
  — one HTTP chunk per event with real gaps, `connection: close` so request
  order equals turn order, every request body captured for assertion, and
  enough OpenAI-flavoured `delta.tool_calls` support to stream a tool call,
  take its result, and stream a final answer. Five tests, and **one real product
  defect found and fixed**.

- **Why this card existed, and what it reveals about test coverage.**
  `tests/tui.rs` had thirteen tests and pointed its gateway at
  `https://gateway.invalid`. **Nothing had ever rendered a streaming turn or a
  tool call through the viewport** — the tests covered `/help`, the palette,
  resize and quit. The milestone's remaining twelve stories are all about what
  the viewport does *during* a turn, so none of them could have been tested
  honestly before this.

  The lesson generalises: a suite can be large, green and carefully written and
  still never exercise the thing the next milestone is about. Thirteen passing
  tests and an unreachable base URL looked like coverage.

- **The defect (F47).** In classic styled mode, an answer whose final line has
  **no trailing newline** — the usual provider shape — was written to the
  terminal and then **erased**. Deterministic across 20 runs in both profiles;
  inline mode unaffected, which is what localised it.

- **The first hypothesis was wrong, and the discipline that made that cheap is
  the point.** The test author proposed that `finish_line`'s two separate writes
  left a window for a live-row writer — and **labelled it a hypothesis** instead
  of asserting it.

  It was wrong in its central claim. The fixer **instrumented `kitsu-render`**
  and found `print_fragment` never appears in the trace: in classic mode with
  tools advertised, deltas are **buffered rather than streamed live**, and the
  answer is printed in one shot by `print_message`. The path the hypothesis
  blamed was not running.

  **Verified cause:** `print_message` renders inside the live-row suspension,
  and for text not ending in a newline that suspension **closes with the cursor
  mid-row** on the row holding the last line. The guard's `Drop` repaints with
  no absolute positioning — on that same row — and `finish_line`'s following
  `clear_row` wipes the remainder. `SUSPEND_DEPTH`, `write_block` and the
  spinner thread are all innocent; the defect is single-threaded.

  This is the second card in a row where a reported mechanism turned out to be
  wrong, and the contrast matters: **F43** cost a wrong finding and a wrong brief
  because I recorded a mechanism as fact; here the same class of error cost
  nothing, because it was labelled a hypothesis and then settled by
  instrumentation rather than argument. A "hypothesis" label is not hedging — it
  is what tells the next person the claim is still open.

- **The fix is at the layer where the broken invariant lives.** The region's
  painters are **relative** (`\r\x1b[2K`, `\x1b[1A\x1b[2K`), so each acts on
  whatever row the cursor occupies; the unwritten contract was *the cursor is at
  column 0 of a row the region owns*. A `PARTIAL_LINE` flag lets a writer
  declare that it ended mid-row, and the region steps down one row at the single
  point where it takes a fresh row.

  The alternatives were each worse and were ruled out with reasons: having
  `print_message` emit its own trailing newline would change plain and
  non-TTY stdout bytes — 240 byte-contract tests — and double up with
  `finish_line`'s newline; suppressing the repaint would lose the spinner and
  draft row. `\r\n` rather than `\n` because raw mode touches `c_lflag`
  only, so `OPOST|ONLCR` still applies — correct in both modes. Inline mode is
  inert: `render_region` is only reached when live rows are supported, which is
  false there, and the `ESC[1;23r`-exactly-once and wide-wrap assertions still
  hold.

- **A parity gap reported without inventing a requirement for it.** In inline
  mode the submitted prompt is **never committed to the transcript** — classic
  shows `kitsu> say hello` on its own row; inline goes straight from splash to
  the answer, and the draft text appears nowhere in the session's bytes. The
  author left this **unasserted** because the plan requires only that typed
  input "appears and submits", which it does, and flagged it for **T3-S7**,
  which owns the "same transcript receipt" work. Correct call: a test author
  inventing acceptance criteria is how a suite acquires assertions nobody
  agreed to.

- **Documentation (standing requirement, in this commit):** `docs/ux-design.md`
  — whose own rule is that code and it are fixed in the same change — gains the
  **relative-positioning invariant**, which was never written down and is why a
  writer could violate it silently; it now states that "at the transcript
  bottom" is literal and that **any new writer able to finish without a newline
  must declare it**. `CHANGELOG.md` carries the user-visible fix. **F47**
  recorded with the wrong hypothesis preserved, and the plan row updated.
