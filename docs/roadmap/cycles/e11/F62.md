# E11 / F62 — a config key with no consumer, refused from both doors

- **UTC start/end:** 2026-10-16T21:30Z / 2026-10-16T14:13Z
- **Branch/base:** `features/tui_herdr_improvements` / `741e315`
- **Epic/story/card:** E11 / **F62**, reopened after the ring was fed. **Stopped
  once on a design hole in my own card.** Records the ten-site doc sweep.

- **The defect.** `[tui] alternate_screen` was parsed, validated, defaulted and
  **consumed by nothing**. All three values did the same thing — so `auto` was
  accidentally right and **`never` was a lie**, including for the exact case
  `README` named: *"for multiplexers where the alternate screen misbehaves."*
  **A promise is most costly to the reader who needs it most.**

- **F62's stated blocker was gone.** It said closing this needed the cell ring fed
  so an in-viewport restore had a source; the ring has been fed in production for
  several cards. The **second render path** still does not exist — but that made
  the card a refusal, not a feature.

- **The stop that improved the card.** My brief said refuse the config value. The
  test author found that would close nothing: **`--no-alt-screen` is a live global
  flag documented as a one-way force**, so refusing only the file **moves the lie
  from the config to the command line**. My ruling: **refuse both doors**, because
  they are one capability and a flag that silently does nothing is the identical
  defect to a value that silently does nothing.

- **Argv validation, every subcommand, including `doctor`** — the author flagged
  this as a scope call and I kept it: `doctor` is where a user goes to learn
  whether their setup is sound, so a silent lie there is worst; and a global flag
  refused on some subcommands and accepted on others is **a rule the user must
  memorise**, where uniform refusal is predictable.

- **“Not available yet”, never “not valid”** (**F90**): the value is a coherent
  thing to want and kitsu intends to honour it, so the message must tell the user
  to **wait** rather than to stop wanting it.

- **Recognised ≠ accepted.** One const could not serve both messages: a typo like
  `Never` still gets the **vocabulary** error listing all three **recognised**
  spellings, while the refusal lists the two **accepted** values. The guard test
  pins it, because *telling someone who typed `Never` to wait for a feature they
  could have had would be the wrong kind of wrong.*

- **Two things the implementer got right unprompted.** The argv message **avoids
  the substring `invalid value`**, so an older test asserting that stderr carries
  neither `unexpected argument` nor `invalid value` **still passes untouched** —
  the flag still *parses* and is then refused. And when nothing constructed
  `AlternateScreen::Never` the compiler warned; rather than delete the variant it
  **kept it with a dead-code allowance**, because deleting it would turn
  *"recognised, not yet available"* into *"not a value"* — **F90 applied to a type
  rather than to prose.**

- **The doc sweep found ten sites, not the three I was handed** — and a
  disagreement neither agent could see from its own three: **`:1408` says the flag
  forces `inline`** while **`README` said it forces `never`**. A renderer versus a
  screen value; forcing a renderer would also disable fullscreen, a much larger
  promise. **Recorded for T5-S4, which owns the implementation.** The design had
  recorded the gap honestly at `:480` all along — so **the gap was documented
  where implementers read and promised where users read**, which is the worse
  direction.

- **Acceptance, both profiles:**
  ```
  --workspace --exclude kitsu 1153 · --bins 983 · --test cli 258 · --test tui 75
  paste_latency 4 · carrier_matrix 7 · build_provenance 2
  cargo clippy --workspace, both, -D warnings   0 warnings
  ```
  Two mutations re-run: *not valid* (4 tests catch it) and over-broad refusal of
  `always` (the guard catches it). The maintainer's `fs.rs` is at `54 20`.

- **The practice worth making standard:** the test author proved **mutation A** —
  the intended refusal makes all five file-side tests green — **before** hand-off.
  Eleven unsatisfiable assertions this epic were found in review or by an
  implementer hitting a wall. **A test author who has built the fix once knows the
  tests are reachable, and nobody else can know it as cheaply.**
