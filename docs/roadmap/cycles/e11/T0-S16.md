- **Requirement:** **R4** — met apart from `@file` completion and highlighting.

- **What shipped.** Typing a slash prefix at the inline prompt opens the
  bordered palette above the composer. It grows and narrows as you type, is
  built smaller on a short window rather than clipped, closes when the prefix
  stops being one, and survives a terminal resize at the right height. Every
  keystroke repaints **every** pinned row, so the list can never show matches
  for a prefix already changed.

- **F29's refactor came first, and "behaviour-preserving" was demonstrated
  rather than asserted.** `slash_palette_rows` now owns the labels, both frame
  sets, the entry formatting, the row cap and the "N more" step; `slash_palette`
  is a thin join over it. The implementer ran the suite **between** the refactor
  and the wiring and saw the identical 6 + 1 failures with nothing new and
  nothing newly green — which is what that phrase has to mean in practice. I
  verified the duplication is gone by classifying every occurrence rather than
  trusting the summary: the label exists **once** in production, four lines into
  the shared function; the two other non-comment hits are assertions in the
  classic path's own tests.

- **Three things the test author got right that are worth keeping.**
  1. It put the seam on the **guard**, not inside the reader, with the reason:
     the paint closure belongs to the caller, so a reader-level test would
     assert against its own painter and could never observe a partial repaint.
  2. It pinned repaint-every-row per F27 — on the bytes a **single** paint
     emits, recovering the absolute lines touched, after splitting off the
     re-latch's own teardown. And it explained why row-count is the only honest
     instrument: no one-keystroke pair exists with equal height and different
     palette text, since a longer prefix matching the same count matches the
     same set.
  3. It chose "preserve the current height" for resize over "repaint
     immediately", because the alternative makes correctness depend on an
     *ordering* between the re-latch and the next paint — and it pinned that
     the height is genuinely latched, not merely emitted, so a cosmetic fix
     cannot pass.

- **Review findings and fixes:**
  1. **Two unsatisfiable assertions, both verified independently before
     accepting.** This is the second time an implementer has claimed "the test
     is wrong", so I checked rather than took it, and both held up.
     - The dismissal test counted painted rows across the **whole** tail, but
       the re-latch's teardown already clears row 24, so painting the composer
       there makes two and the asserted count of one is unreachable. Its sibling
       test splits the teardown off first; this one did not. Fixed the same way,
       with the reason in a comment.
     - The pseudo-terminal test's final check looked for a three-parameter
       cursor sequence the viewport never emits, or for `ESC[1;6r` — the
       viewport **height** where the region's bottom **margin** was meant. The
       child demonstrably emits `ESC[1;18r`. Fixed to `ROWS - height`.
  2. **A rule the card did not ask for, accepted with its cause recorded.** The
     palette stands down when a showing hint is not the lead entry's own
     completion. The implementer's own doc comment says why: the during-turn
     priority list overrides registry order. That is **symptom-level** — it
     suppresses a correct palette because an inappropriate hint disagrees — and
     the cause is mine, recorded as **F30**: T0-S9/S10 reused
     `typeahead_slash_hint` at the idle prompt, carrying a policy named
     `MID_TURN` into a context where no turn runs. Accepted here because all
     thirteen pseudo-terminal tests and all nine unit tests agree under it and
     it is explainable; the principled fix is carded.
  3. Accepted no caching (the palette is a few `format!`s over a static
     registry, once per read chunk) and `paint_composer` for the post-read
     reset, since `paint_draft` would leave a stale frame pinned above a
     one-row repaint.
