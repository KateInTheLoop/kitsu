# E11 / T2-S3 — the `Blocked` vocabulary, and a wire version with it

- **UTC start/end:** 2026-10-14T07:52Z / 2026-10-14T08:57Z
- **Branch/base:** `features/tui_herdr_improvements` / `c4bd57b`
- **Epic/story/card:** E11 / T2-S3, **taken before T2-S2** (reason in the plan
  beside the rows).
- **Requirement:** **B5**, in full; **B4**'s JSONL clause. Records **F34**.

- **Why before S2.** S2 defines the channel an approval request travels on, and
  that channel's destination *is* the `Blocked` state this card introduces.
  Building the channel first would mean inventing its destination twice. S3 is
  also self-contained and unblocks nothing else, so moving it earlier cost
  nothing.

- **What T1 had already built, which made this card small.** The display side
  was in place with guard tests asserting it was unreachable: the live status
  row renders `[N blocked] ` with blocked **outranking** running,
  `/jobs view` has a `needs input` group ordered **first**, and
  `AgentRegistrySnapshot::blocked` existed as a literal 0. So this card supplied
  a vocabulary into plumbing that had been waiting for it — the payoff of a
  decision in T1-S1 that looked like dead weight at the time.

- **The compiler enumerated the work.** Adding one variant to three enums broke
  15 exhaustive matches, and that list *was* the card: 6 `AgentStatus`, 5
  `AgentThreadPhase`, 3 `AgentProgressStatus`, 1 struct literal. Every label
  landed as specified and nothing wanted a different one.

- **One label choice carried real weight.** The `/jobs` JSON `status` string is
  a wire contract, and `blocked` was chosen so the field name
  (`AgentRegistrySnapshot::blocked`), the wire value, the `/jobs view` heading
  and the design text all agree. A spelling like `needs_input` or `waiting`
  would have made the field and the wire disagree. The same word feeds three
  readers — the deck row, the hook's `STATE=`, and the JSON — through one
  function.

- **The counts line appends rather than inserts.** ` · {n} blocked` goes after
  `cancelled` specifically so an existing assertion that matches the line as a
  **prefix** stays valid. That is the kind of detail that turns a one-line
  change into a broken test suite if taken the other way.

- **Four decisions that were mine:**
  1. **`DeckState::Running` for a blocked agent**, because `kitsu-render` has
     no `Blocked` variant and B5 does not extend that crate. Recorded as
     **F34** with the cost stated plainly: the deck glyph is identical to a
     running agent's, and only the word distinguishes them. Three other signals
     already catch it, but the glyph is the densest one and this belongs in T4.
  2. **`AgentStatus::Blocked` stays a unit variant**, unlike its siblings that
     carry a `String`. Nothing carries a reason yet; the smallest honest
     surface wins, as with T2-S1's route payload. If S4 needs a payload it is
     one construction site, to be called out rather than reshaped silently.
  3. **Add `"blocked"` to `jobs_snapshot_payload`** even though no test can
     exercise it yet, so the payload keeps mirroring the deck counts
     key-for-key. Deliberately unpinned until S4 owns its test; an inconsistent
     payload is worse than an untested key.
  4. **Correct an inaccurate doc comment** at `agent_hook.rs:206`, which
     claimed a fixed-size `ALL_STATUSES` array would break when a variant was
     added. It would not — which is exactly why the explicit label test exists.

- **Review findings and fixes:**
  1. **One test edit was unavoidable and I accepted it**: a test-side
     `match` over `AgentThreadPhase` was itself one of the 15 compile errors.
     The implementer added the mechanical arm only, changing no assertion,
     fixture or case list.
  2. **One `#[allow(dead_code)]` was needed** for the zero-warning gate, on
     `AgentStatus::Blocked`, because nothing in production constructs it yet.
     Annotated with why and with existing precedent in the crate; **T2-S4 must
     remove it** when agents start parking.
  3. Verified rather than accepted: both unreachability guards pass untouched,
     `AgentRegistrySnapshot::blocked` is still a hard 0, and the maintainer's
     `fs.rs` is at `54 20` with no `rustfmt` run on `kitsu-tools`.

- **A documentation error of mine, found while writing this up.** I checked
  whether the schema bump is externally observable rather than assuming, and it
  is: the DTO is serialized into `/jobs --json` at two call sites. So
  `thread.schema_version` now reports **2** to anyone parsing that output, and
  `thread.name` may appear — which is a wire change and earns a **Changed**
  entry in the changelog. It also exposed that the plan's own baseline row
  **conflated two independent schemas**: it warned that a v2 reader would reject
  v1 *state files*, but `agent_state_file.rs` has its own schema and never
  embeds the thread DTO. That row is now corrected in place; T1-S5's
  "tolerates `schema_version ≤ current`" refers to the state file, not this.
