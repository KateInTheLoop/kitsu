- **Requirement:** **N2** measured. Records **F60** and F39's fifth occurrence.

- **N2 holds with large margin.** A 10 KiB bracketed paste at the idle prompt:

  | profile | inline | classic | budget |
  |---|---|---|---|
  | debug | **4.2–5.6 ms** | 3.1–3.7 ms | 100 ms |
  | release | **0.7 ms** | 1.1 ms | 100 ms |

  About twenty times inside the budget in debug, over a hundred in release,
  across six consecutive runs with a ~2 ms spread. **Nothing was tuned.**

- **The benchmark earns its number, which is the hard part of a measurement
  card.** A benchmark that times the wrong thing reports a comfortable figure
  and proves nothing — the measurement equivalent of **F58**'s unsatisfiable
  assertion, except it reassures instead of failing.

  The endpoints are defined and defended: **t0** is the instant before the
  bracketed burst is written, with the child at a *settled* idle prompt — raw
  reader engaged **and** the stream quiet for 400 ms, because startup's banner
  goes out through direct writers that are not synchronised with the reader
  engaging, and a paste timed into that would be timing the banner. **t1** is
  when the composer row containing the payload's last 23 bytes — a sentinel —
  reaches the master.

  That endpoint asserts the three things N2 is actually about **at once**: the
  child consumed the whole burst (the sentinel is its tail), kept it as **one
  draft** (a split at a newline would have submitted the first line, and the
  tail would never become a composer row), and **painted**. The payload carries
  newlines and tabs throughout so "one draft" is a real claim. Rejected
  endpoints are recorded with reasons: the last byte *written* measures the pty
  buffer (and indeed reads 0.0 ms), a later keystroke folds in its own latency,
  and quiescence measures a timeout.

- **It proved the benchmark is not a tautology, twice.** The harness asserts the
  sentinel is **absent** from everything read before t0, so a sentinel already
  on the wire fails rather than reporting 0 ms. And it **falsified on purpose**:
  with the burst suppressed and nothing else changed, the inline run read
  **zero** bytes for the full deadline and failed — so an idle inline composer
  emits nothing at all, and every byte in the measurement is the paste's. Both
  the check and the falsification are written into the module docs.

- **Reported, not gating, as the row requires.** The *correctness* of the paste
  gates — sentinel absent before, present after, inside the deadline. The
  **time never fails the test**. The numbers print to stdout and stderr so they
  survive capture, and `KITSU_N2_STRICT=1` asserts the budget for a run where
  the number is the point. Nothing is `#[ignore]`d, on the reasoning that an
  ignored benchmark is one nobody reruns — it costs under a second.

- **F60 — the exit gate has a clause with no test, and I would have missed it.**
  Four of five clauses ran and passed. The first cannot run, for two independent
  reasons: there is **no two-tool-call streamed PTY run** (the nearest is one
  tool call, classic only), and **per-fd separation is structurally impossible**
  in the harness, which hands the child three `dup`s of **one** pty slave — so
  stdout and stderr are the same descriptor and there is no "inline's stdout" to
  compare.

  The agent also named the test that **does** pass and said it must not be
  mistaken for this clause: the permission-receipt equality is **R7's** gate, one
  line on one fd-blind stream. That distinction is the finding's value — the
  clause would have been read as covered because adjacent tests have similar
  names. Same lesson as **F57** from the other side: **a gate is only as real as
  the test implementing it, and "there is a test about this area" is not that
  test.** The card is specified in F60 rather than left as a note.

- **The documentation sweep found that I had overstated a feature, in
  functionality.md, in T3-S3.** I wrote that the inline composer "offers `@file`
  path completion … both hosts call one completion source" — describing the
  **seam and its parity test as shipped behaviour**. It is not:
  `InlineComposerHost` still carries `#[allow(dead_code)]` and its own comment
  says nothing in production drives it. Corrected to split the claim — slash
  completion and the palette work, `@file` does not, and the sweep protects them
  from drifting **once connected**.

  **And `ux-design.md` contradicted itself.** A heading read "completion and the
  palette do not [work]" while the same section documents the working palette
  ~140 lines above; the palette renders in production
  (`paint_composer` → `palette_rows`). Both passages corrected, with a note
  that **each of that passage's three claims has now been wrong at least once** —
  Tab was wrongly bundled in, the palette was wrongly called absent, and only
  `@file` was ever right. That is **F20**'s lesson for the fourth time: a list
  of "what is missing" written from memory of a design is unreliable.

  **`ui_guidelines.md` was a 26-line stub with a false statement** — it named
  `✨` as the thinking indicator, a glyph appearing in **zero** source files,
  while the four the product actually uses (`◆ ◇ ◉ ◈`) were absent. Rewritten
  to state what the code does, document the two renderers, and carry the five

  **The README's flag table was missing `--tui` and `--no-alt-screen`** —
