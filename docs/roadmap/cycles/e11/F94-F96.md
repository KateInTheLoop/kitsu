# E11 / F94 + F96 — the exit paths a new terminal mode did not revisit

- **UTC start/end:** 2026-10-15T20:30Z / 2026-10-15T20:09Z
- **Branch/base:** `features/tui_herdr_improvements` / `214f8d8`
- **Epic/story/card:** E11 / **F94 with F96 folded in**. Records F96's second
  cause.
- **Requirement:** **N5** — every clause now met on every exit path.

- **What shipped.** The dying-signal handler gives the alternate screen back
  **when it is held**, for both surfaces that take it; the panic hook does the
  same, including off the main thread; and a session **started** in fullscreen
  now installs a handler at all, with a termios fallback for the case where
  nothing in the process holds a snapshot.

- **The hole was older and wider than I recorded.** I filed F94 as fullscreen's
  problem. Verified: `ESC[?1049l` existed in exactly three places — a const, a
  doc comment, and the **agent view's normal-path restore** — and the dying
  handler wrote the title pop but not the screen. **So a `SIGINT` with the agent
  view open has stranded users on the alternate screen since T4-S2**, five cards
  before fullscreen, which inherited the hole and made it longer-lived.

  **Why nothing caught it:** the handler already popped the title, so it *looked*
  like it handled screen-level state — and it was written before anything in this
  binary took the alternate screen. **The overlay added a terminal mode and never
  revisited the one place that undoes terminal modes on the way out.** No test
  killed the process mid-overlay; the absence was the defect.

  That is **F79**'s rule in reverse: *when a surface starts taking new terminal
  state, every exit path is a suspect — and exit paths are enumerable* (normal
  return, `/quit`, a dying signal, a panic). The overlay covered one of four.

- **F96, folded in, and worse.** `install_exit_restore` is called only inside
  `if installed.is_some()`, and `install` is deliberately inert for fullscreen —
  so `--tui fullscreen` installed **no handler at all**. `Ctrl+C` restored
  nothing: no region, no title, no screen, **no termios**. The terminal was left
  in raw mode, needing `reset` typed blind. **Shipped one card earlier, mine.**

  **It is the intersection of two individually correct decisions** — fullscreen
  pins no region, and the handler was installed where the region was. Nothing is
  wrong with either. **Conjunctions are what neither a per-card test nor a
  per-requirement review looks at.**

- **My "probably harmless" suggestion was refused by measurement.** I floated
  appending the leave sequence unconditionally. It is not a no-op on the primary
  screen: it restores the cursor to its saved slot, so a `SIGTERM` in an ordinary
  session would drop the shell's next prompt onto the user's transcript. The test
  author proved it by prototyping the unconditional form and watching **two guard
  tests go red** — guards written for exactly that purpose.

- **And "the handler is missing" was two defects with one symptom.** Installing
  it was not enough, and the new test's **first run** proved it: the handler wrote
  the full restore and the pty still read `ICANON=false ECHO=false ISIG=false`.
  `CANONICAL_TERMIOS` is published only by `RawStdinGuard::engage`, and a
  fullscreen-start session's raw mode is **rustyline's** — so the handler had
  nothing to restore. It now falls back to `tcgetattr` + `ICANON|ECHO|ISIG` +
  `tcsetattr`, all async-signal-safe, with a failing `tcgetattr` leaving the
  terminal as the signal found it.

  **Only a test asserting the terminal's observable state separated the two.**
  The bytes were already correct while the terminal was still broken — which is
  why **F71**'s rule (assert what is observable, not what was written) matters at
  the system level and not just in a renderer.

- **Three things the implementation got right that I did not specify.** The flag
  is set **before** the take and cleared **after** the give, so no window reads
  "free" while the screen is held — *the window it excludes is the defect
  itself*. The with-screen constant is **composed at compile time** from the two
  existing ones, so there is no third copy and `SIGNAL_RESTORE` stays a prefix,
  which keeps an existing `contains` assertion and a byte-parity test green
  untouched. And the **double-restore** case was closed: a main-thread panic in
  fullscreen would have had both `Drop` and the hook writing a leave, so the hook
  clears the flag after writing.
