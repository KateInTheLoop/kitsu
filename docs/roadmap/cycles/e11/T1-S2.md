# E11 / T1-S2 — ambient background-agent tag on the classic live status row

- **UTC start/end:** 2026-10-13T15:37Z / 2026-10-13T16:02Z
- **Branch/base:** `features/tui_herdr_improvements` / `0ca9d99`
- **Epic/story/card:** E11 / T1-S2 / first card
- **Requirement:** A8, consuming the snapshot counts T1-S1 added. A detached
  agent announces itself once through `background_agent_notice`; after that
  line scrolls away, a user mid-turn has no way to see that agents are still
  working or that one needs an answer. The live status row already carries a
  dimmed `[N queued]` tag for exactly this reason, so the agent tag joins it.

- **Design deviation, deliberate and recorded.** R5 as drafted specified
  `← N agents`, copied from Claude Code where `←` is a live hint for the
  left-arrow key that opens its agent view. Classic mode has no such binding
  and will not until T4-S2, so shipping the arrow would promise a key that
  does nothing. This card ships the bracketed form `[N blocked]` /
  `[N agents]` matching its neighbour, and R5, A8, and §4.6 of the design
  were amended in this commit to say so and to allow the arrow only once the
  affordance exists.

- **Evidence and expected failure:** 8 tests written first against an absent
  function and a changed arity. Observed:

  ```
  error[E0425]: cannot find function `agents_tag` in this scope
  error[E0061]: this function takes 4 arguments but 6 arguments were supplied
  ```

  13 errors: 11 E0061, 2 E0425.

- **In scope:** the pure `agents_tag`, its width in both the row composer and
  the wrap-segment function, the two state fields, the `live_agents_state`
  setter, the collector sync, and the design-doc amendment.
- **Out of scope:** any TUI renderer, the `←` form, consuming
  `unacknowledged` (deferred to the full status row in T3-S5), and any change
  to notice text or stack rows.

- **Authority/failure/version/rollback notes:** no authority surface. No new
  terminal write: `live_agents_state` is state bookkeeping plus the shared
  `redraw()`, which is already gated by `live_rows_supported()`, so non-TTY,
  `--plain` and assistive output stay byte-identical (N1) and
  `--reduced-motion` simply shows the tag statically (N9). Rollback is
  passing zeroes to the setter, which hides the tag entirely.

- **Tests added or changed:** 8 added to `mod tests` in
  `crates/kitsu-render/src/live.rs`. Truth table pinning blocked-outranks-
  running and the singular/plural boundary; dimming and cursor-column shift;
  both tags together asserted by exact sanitized equality so the order is
  pinned, not merely present; no tag on a spinner-only row; a width sweep
  from 40 to 200 columns over four tag states asserting the row never exceeds
  the terminal and the cursor stays inside it; an agreement test asserting
  the tag width from both the composer's and the segment function's side so
  neither can drift alone; a sanitize round-trip; and a narrow-terminal case
  proving the spinner is still dropped first.

  **18 pre-existing test call sites were edited, arity only.** See review
  finding 1.

- **Implementation:** `agents_tag(blocked, running) -> Option<String>` is
  pure and the single source of the tag's width, called by both the composer
  and the segment function, so the two cannot disagree. Its width folds into
  `prompt_width`, which is also what the spinner-yield rule consumes, so the
  spinner still surrenders the row first. The setter mirrors
  `set_spinner_segment` rather than `live_queue_state`. The collector syncs
  from a `watch` borrow before the first paint and once per poll tick.

- **Review findings and fixes:**
  1. **Briefing gap, mine.** Pinning a positional signature forces every
     existing call site to change, and no Rust construct lets one function
     accept both arities, so the 18 old `compose_row` calls had to be updated
     or nothing compiled. I assigned that to neither agent. The implementer
     did it, reported it unprompted, and offered to hand it back. Accepted
     after verifying the pairing line by line: all 24 removed lines account
     for 6 production edits plus exactly those 18 calls, each gaining `0, 0`
     before its queued argument, with the two non-zero cases (queued 2 and 3)
     and every column width preserved, and no assertion, expected value, or
     test name touched. Future cards that change a shared signature must name
     the call-site owner in the brief.
  2. Verified by reading, not by report: the setter leaves `region_dirty`
     alone. It is called every poll tick, and marking the region dirty would
     repaint the queue stack rows on every count change.
  3. Verified the collector sync sits after both `APPROVAL_INPUT_ACTIVE`
     checks, so nothing runs while the approval reader owns stdin and the row
     is torn down.
  4. Accepted gap: the two state fields and the setter's early-return have no
     test. `LiveRowState` lives behind a process-global `OnceLock<Mutex<..>>`
     and the suite's precedent is to test composition purely and state only
     by building a local `LiveRowState` and calling `render_region`;
     `live_queue_state` is likewise untested. Verified by reading against
     that precedent instead of inventing a global-state test.
