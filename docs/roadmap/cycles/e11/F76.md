- **What shipped.** `Ctrl+X d` keeps a line in progress: `InlineRead::Detached`
  now carries the composer's contents and the loop replays them into the next
  read. One production line changed.

- **The defect.** The variant's doc comment said the draft was not carried back
  *"because this outcome is only ever reached on an empty one"* — **true of `←`,
  which requires an empty composer, and false of `Ctrl+X d`, which has no such
  precondition.** So the chord cleared whatever you had typed. **A variant
  documented by the narrowest route that reaches it:** the comment was accurate
  when written and became wrong when a second caller arrived — **F69**'s and
  **F70**'s mechanism one level down, in the type system.

- **The cheap fix was wrong, and the agent's reason was better than mine.** Giving
  the chord an empty-composer precondition would have made the comment true at no
  cost. I rejected it because the chord exists for the case `←` cannot serve. The
  test author found the sharper form: **with an empty composer the chord is
  already redundant** — `←` detaches on the first press and is **not** gated by
  `[tui] left_arrow_opens_agents`, so there is no keymap in which `←` is
  unavailable but the chord is. **The chord's only non-redundant case is exactly
  the one the cheap fix would forbid.** It also checked the chord was not a
  deliberate-versus-slip distinguisher: unattached it is **inert and silent**, and
  `/detach` is where a deliberate detach gets an answer.

- **It inverted my own instruction, correctly.** I authorised nine test sites and
  warned against weakening an assertion to a wildcard where the exact value is
  knowable. Two of the nine are **negative** controls ("with nothing attached,
  neither key can detach"), and there a wildcard is **stronger**:
  `assert_ne!(x, Detached(String::new()))` would pass if the reader returned
  `Detached("oops")`. Those two became `assert!(!matches!(.., Detached(_)))`;
  the other seven are **exact** payloads. **No positive assertion became a
  wildcard.**

- **F79's rule applied as instruction, not background.** The card changes a
  variant's shape, so its consumers were **enumerated**: two production returns
  (the `←` arm, honest with an empty payload; the chord arm, the defect), two
  production uses, one prose mention. No other crate names it.

- **The seam, and why it is the right kind.** The composer loop needs a real tty,
  so its detach arm was untestable; the test author added
  `apply_inline_detach(attached, draft) -> String` — one seam, one call site,
  mirroring `apply_agent_view_exit` and `apply_jobs_view_exit` on the attach
  side. Making the unreachable thing reachable is **F71**'s and **F75**'s lesson
  applied before the fact, and it is the fourth card to use the
  prototype-then-revert method for reachability (**F61**).

- **A README line of mine that this change made false.** Last card I wrote that
  `←` and `Ctrl+X d` "do the same thing silently". They never quite did, and now
  they differ visibly — the chord keeps your draft and works with text typed.
  **Corrected here, along with the CHANGELOG and `functionality.md`, which now
  say the two routes are not interchangeable and why.** This is the drift the
  standing requirement warns about, introduced by me one card earlier.
