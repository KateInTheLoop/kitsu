# E11 / T1-S3 — `/jobs view`: the agent deck grouped by state

- **UTC start/end:** 2026-10-13T16:07Z / 2026-10-13T16:41Z
- **Branch/base:** `features/tui_herdr_improvements` / `24c22a4`
- **Epic/story/card:** E11 / T1-S3 / **first card of the story**. The plan
  names `/jobs explain` in the same story; it is deliberately a later card, so
  this record covers `view` only.
- **Requirement:** A2. With several detached agents the flat, id-ordered deck
  makes the user scan every row to find the one that needs them. `/jobs view`
  presents the same data grouped by state, needing-input first.

- **Evidence and expected failure:** 14 tests written first — 12 unit plus 2
  scripted end-to-end. Observed:

  ```
  error[E0425]: cannot find function `format_jobs_view` in this scope
  ```

  11 occurrences. The test author also stubbed the function temporarily to
  prove the behavioural failures (587 passed, 11 failed) and reverted the
  stub, so the tests were known to fail for the right reason and not merely
  to be uncompilable. Two of the 14 pass on day one by design and are
  regression guards: one pins the flat deck's shape against the row-helper
  extraction, the other pins `/agents <id>` against the alias widening.

- **In scope:** `format_jobs_view`, the shared row helper and counts
  expression, the `view` arm in both dispatchers, the alias widening, the
  suggester and registry entries, and the documentation.
- **Out of scope:** `/jobs explain`, any `blocked` state, adding the missing
  `close` to the suggester list (finding F2).

- **Authority/failure/version/rollback notes:** no authority surface, no
  schema change. The JSONL payload gains only a new `action` value on an
  existing event shape, which `docs/jsonl-protocol.md` permits within v1.
  Rollback is removal of the `view` arms; the shared helper extraction is
  behaviour-preserving and can stay.

- **Tests added or changed:** 14 added, none changed. Grouping order asserted
  by byte offsets rather than mere presence; order proven independent of
  creation order by scrambling ids against states so an id-ordered
  implementation prints the groups backwards; the done split proven to follow
  the handoff, with `peek_result` deliberately not moving a row and
  `acknowledge_result` moving it; headings asserted to be exactly
  `"  <heading> (N)"`, glyph-free and `is_ascii()`; both views' headers proven
  byte-equal after substituting the lead, and their row and detail lines
  proven equal by `assert_eq!` so duplicated row logic would fail; indents
  pinned at 2/6 flat and 4/8 grouped; plus suggester and command-registry
  guards. End-to-end: a scripted JSONL run asserts `/jobs view` and
  `/agents view` both return `action: "view"` with the alias stamped, and a
  **non-JSONL** run asserts `/agents 7` still reaches `show`.

- **Implementation:** one shared `agent_deck_row_block(agent, collected,
  row_indent, continuation_indent)` used by both formatters, one
  `jobs_deck_counts` expression used by both headers, one shared empty-deck
  constant, and a `jobs_view_group` classifier over a fixed six-group array.
  `needs input` has no classifier arm, so it is unreachable rather than
  merely empty; a later story adds the arm. The alias arm's error branch
  became a verbatim forward, so every `/jobs` subcommand is now reachable
  through either name while the empty and numeric forms are untouched.

- **Review findings and fixes:**
  1. **My specification was wrong and the test author caught it.** I dictated
     heading literals containing an em dash while also requiring "plain ASCII
     ... identical in all three output tiers". Those are contradictory: the
     plain tier promises zero non-ASCII bytes and `ascii_structural_markers`
     maps `—` to `-`, and unlike the header these headings bypass
     `sanitize_plain_inline`. Resolved by changing the literals, not the
     requirement: `done, result ready` and `done, collected`. The author also
     added an `is_ascii()` assertion so the tier rule fails directly instead
     of surfacing as an exact-equality mismatch only under `NO_COLOR`.
  2. **My survey of existing coverage was wrong.** I reported that `/jobs`
     had no end-to-end tests; the author found the scripted JSONL case that
     does cover it. My grep missed it because the script is one embedded
     string where `/jobs` is followed by `\n`. That changed the standard for
     this card from read-only verification to real end-to-end assertions,
     and the author was sent back to add them.
  3. **A worthless test caught by its author.** The `/agents <id>` guard was
     first written under `--jsonl`, where the forwarded and rejected paths
     emit byte-identical framed failures, so it could not distinguish them.
     Moved to a non-JSONL run asserting the distinguishing stderr text.
  4. **Reviewer change after the gates passed.** The alias now forwards every
     subcommand, but the registry advertised `[view|id]`, which actively
     implies `/agents stop 3` is invalid. Changed to
     `[view|<id>|any /jobs subcommand]`; the registry guard test still passes.
  5. Verified by reading, not by report: the extracted empty-deck constant
     keeps its original leading newline and two-space indent, and the flat
     deck's header rebuilds identical bytes, so `format_jobs` output is
     genuinely unchanged.
  6. The implementer hit `clippy::type_complexity` with an array of predicate
     function pointers and replaced it with a classifier returning a
     `&'static str`. Better code; noted because the simpler shape was not the
     first one tried.

- **Residual risk:** a populated `cancelled` group is untested, because

  absence is pinned. A populated `needs input` group is unreachable until the
  blocked state exists. Neither dispatcher's `usage:` text is asserted, so
  `view`'s discoverability rests on the suggester and registry guards.
