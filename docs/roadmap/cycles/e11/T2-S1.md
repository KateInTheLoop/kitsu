# E11 / T2-S1 — the prompt route, and nothing else

- **UTC start/end:** 2026-10-14T07:24Z / 2026-10-14T08:24Z
- **Branch/base:** `features/tui_herdr_improvements` / `187e120`
- **Epic/story/card:** E11 / T2-S1 — **first story of milestone T2**, blocked
  agents.
- **Requirement:** **B2** and design §4.4. Corrects **F33**.

- **Why this milestone matters, in one sentence.** Today a detached background
  agent that hits a permission gate **fails closed** — there is nobody it can
  ask — so the action is simply refused. T2 makes it park in a `Blocked` phase
  that a human can answer from the foreground. This card builds only the seam
  that makes routing possible.

- **What shipped, and what deliberately did not.** The boolean task-local
  `INTERACTIVE_PROMPTS_ALLOWED` becomes `PromptRoute`:
  `Foreground | Denied | Registry { agent_id }`. `interactive_prompts_allowed()`
  is now literally `matches!(prompt_route(), PromptRoute::Foreground)`, an unset
  task still defaults to `Foreground`, and `scope_without_interactive_prompts`
  keeps its name and signature while setting `Denied`.

  **No behaviour changed.** A `Registry` route reports
  `interactive_prompts_allowed() == false`, so both gates keep failing closed
  exactly as today; nothing routes anywhere yet and no gate was touched. That is
  correct for a first story, and it makes the seven existing
  `scope_without_interactive_prompts` call sites and their tests the regression
  net.

- **A question I asked rather than answered, and the agent's answer was better
  than my instinct.** `Registry` must eventually carry a channel for the
  approval request, but defining that needs the request and answer types from
  T2-S2 and T2-S4. I asked for the smallest payload this card could honestly
  pin, explicitly allowing "carries nothing yet".

  It chose `Registry { agent_id: u64 }` and argued it: the id is the one thing
  the route needs regardless of how the channel is later shaped, because the gate
  must say *which* agent to park; `u64` is not a guess, since every registry id
  in `subagent.rs` already is one; and `kitsu-tools` **cannot** name a type from
  `kitsu` because the dependency runs the other way, so a bare integer is the
  only honest spelling available here. It rejected the empty marker because the
  test could then pin nothing but "not foreground", and rejected a speculative
  channel because the message type would be invented here and reworked later.
  It also wrote a `scope_with_foreground_prompts` and **removed it again**,
  declining to demand API the card did not call for.

- **Review findings and fixes — the significant one is my own error.**
  1. **My recorded "safe formatting" rule was wrong, and it caused a second
     incident.** After the test author accidentally reformatted the maintainer's
     uncommitted `fs.rs` with `cargo fmt -p kitsu-tools`, I recorded a rule:
     format only the file you changed, `rustfmt --edition 2021 <file>`. **That
     is unsafe.** Write-mode rustfmt follows the `mod` declarations of the file
     it is given, so pointing it at a **crate root** formats the whole tree — and
     `lib.rs`, the file this card had to change, *is* the crate root. The
     implementer followed my instruction and hit it.

     I had also named the wrong mechanism: I blamed `cargo fmt -p`, when the
     cause is rustfmt following `mod`, which both commands trigger.

     F33 now carries the correction and a flat prohibition — **no write-mode
     rustfmt in this crate** while the maintainer's work is in the tree — with
     `--check` as the read-only alternative. A nuance to be remembered under
     pressure is not a rule.
  2. **Both repairs were precise, and I verified rather than trusted.** The
     implementer reverse-applied **only** the two rustfmt-induced hunks in
     `fs.rs` with `git apply -R`, leaving the maintainer's three untouched, and
     restored `permissions.rs` from HEAD. Verified: numstat back to `54 20`, the
     same three hunk headers as at session start, `permissions.rs` clean, and
     `rustfmt --check` still reporting the same 4 pre-existing violations — the
     crate's unclean state preserved exactly as found.
