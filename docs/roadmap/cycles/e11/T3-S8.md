# E11 / T3-S8 — Ctrl+L, and a terminal that comes back

- **UTC start/end:** 2026-10-14T19:10Z / 2026-10-15T00:17Z
- **Branch/base:** `features/tui_herdr_improvements` / `b62e3ed`
- **Epic/story/card:** E11 / T3-S8.
- **Requirement:** **R8** and **N5**, which this card **amends**. Records
  **F56**.

- **What shipped.** `Ctrl+L` repaints the viewport's pinned row, and
  `SIGINT`, `SIGTERM` and panics now release the scroll region and restore the
  terminal. Before this card every one of those paths left a **pinned DECSTBM
  region** — output trapped in part of the screen until the user ran `reset`.

- **Resize was pinned, not rebuilt.** The author checked T0's three resize tests
  and found they all resized a screen holding **only a draft**, so R8's actual
  wording — "without duplicating **history** lines" — had never been observed.
  One new test prints `/help` first, resizes on the signal alone, and asserts
  the sentinel appears once in the stream and on one row. It **passed first
  try**, so the row's resize half already held. The F26 re-arm was left alone.

- **The non-vacuity work here is the best of the milestone, and it answered the
  exact trap I warned about.** I had said a signal test that asserts "the
  process exited" proves nothing about the terminal, and that a dead pty can
  look clean because nothing is writing to it. The answer: **the pty's line
  settings are set by the child but outlive it.** The harness keeps its own
  descriptor on the slave and `tcgetattr`s it **after reaping**, so a killed
  child is observed leaving exactly the terminal a user must `reset`. That
  assertion cannot pass for the reason I was worried about.

- **Two clauses of N5 were declined rather than faked.** The alt-screen and
  window-title restores describe a runtime with **no caller in the binary** —
  I verified zero references — so nothing pushes a title or enters the alt
  screen, and a test asserting their restore would **pass by construction**. The
  author said so instead of writing it. N5 now records that those clauses are
  **vacuous today, not met**, and become real with T5's fullscreen renderer.
  Saying a requirement is unmet is more useful than a green test that means
  nothing.

- **The cancellation hazard was found, closed, and proved load-bearing by a
  negative control.** A naive restore-and-exit handler **does** break turn
  cancellation, and the mechanism is subtle: in raw mode Ctrl+C reaches the
  editor as a byte and the collector **re-raises `SIGINT` in-process** so the
  turn is cancelled, while `tokio`'s `ctrl_c()` goes through a registry whose
  handler **chains to the previously installed one** — so our handler would be
  invoked on every in-turn cancellation and would kill the session mid-cancel.

  The fix is a flag recording the signal kitsu raises **on itself**, with the
  handler inert for it, sound with no tolerance window because `raise(2)` runs
  the handler **synchronously on the raising thread**, strictly between the
  store and the clear.

  And it was **measured, not argued**: the implementer wrote a temporary
  inline-mode PTY test (deleted afterwards, no test file added), sent a bare
  `\x03` mid-turn, and saw the cancellation notice and a clean quit — then ran
  a **negative control** with the suppression disabled and watched cancellation
  vanish entirely. Our existing cancellation tests are `--plain` and would not
  have caught this.

- **The handler is correct by construction, and I read every line of it.** One
  lock-free atomic load; **one** `write(2)` of a `'static const`; a
  `tcsetattr` of a snapshot captured at raw-mode entry, guarded by a validity
  flag cleared before the copy and set after, so a handler interrupting a write
  **skips** the restore rather than reading a half-written struct; then
  `SIG_DFL` and a re-raise. No `println!`, no mutex, no crossterm, no
  allocation. The panic helper could **not** be reused verbatim — it calls
  `crossterm::disable_raw_mode` and writes through `io::Write` on `Stderr`,
  neither async-signal-safe.

- **The panic path goes through the chaining helper**, so `main`'s broken-pipe
  guard survives: terminal restore → broken-pipe guard → default report. **No
  test can pin this** — the panic hook is process-global with 800+ tests running
  multithreaded alongside — so it rested on the implementation and on my review,
  and I verified it: one `install_panic_restore` call site, `main`'s hook
  untouched, nothing replacing either.

- **F56, closed at review.** The handler's byte string **duplicates** the
  restore helper's output, by necessity — a handler cannot use the helper's
  calling convention. The implementer flagged it and declined to add the test,
  being production-only. Two copies of one sequence with nothing comparing them
  is this project's most-repeated defect shape (F2, F38, F45, the three-file
  args string), so I added the comparison and **verified it has teeth**:
  dropping the title-pop sequence from the handler failed it with both strings
  printed; restoring by checksum passed it. The rule recorded: **forced
  duplication is acceptable only if a test compares the copies** — the copies
  cannot be eliminated, the drift can.
