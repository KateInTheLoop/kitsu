# E11 / F43 — a cancelled approval is recorded, and my own finding was wrong

- **UTC start/end:** 2026-10-14T12:05Z / 2026-10-14T13:26Z
- **Branch/base:** `features/tui_herdr_improvements` / `74ae7f3`
- **Epic/story/card:** E11 / the **F43** fix, taken immediately after milestone
  T2 closed rather than carried into T3.
- **Requirement:** restores the invariant **T2-S6** claimed. Corrects **F43**.

- **Why this card came before T3.** Milestone T2 closed with one known
  correctness defect in a shipped feature. Starting a thirteen-story milestone
  while a feature whose entire purpose is a truthful record keeps an untruthful
  one is poor sequencing, and the fix was small.

- **The finding I wrote was wrong, and the truth was worse.** F43 said a
  cancelled approval is recorded as *"timed out"*. The test author traced every
  call site and disproved it:

  **Cancellation never reaches `resolve_prompt`.** `cancel_matching` — the
  single implementation behind `cancel`, `cancel_all`,
  `cancel_all_with_reason` and `cancel_started_after*` — takes the parked
  prompt **itself** under the registry lock, calls `thread.unblock()`, sets
  `AgentStatus::Cancelled`, and sends `Decision::Interrupt` straight to the
  waiting gate's channel. **No outcome was recorded at all.**

  What a cancelled park actually left behind was a **dangling request**, proven
  from a real `/jobs show`:

  ```
    bounded redacted timeline:
      [1 +0.0s user_task] cancelled while blocked
      [2 +0.0s approval] approval to write a file requested
      [3 +0.0s lifecycle] agent cancelled; result ready for handoff
  ```

  The agent asked, and the record never said what happened. So **T2-S6's claimed
  invariant — every resolution leaves a record — was already broken when I
  accepted that card**: four of five resolutions recorded, the fifth silent. And
  `approval_outcome(Interrupt) => TimedOut` turned out to be *correct*, because
  the only `Interrupt` reaching `resolve_prompt` is the block timer.

- **The lesson is about me, and it is the most useful thing in this card.** I
  wrote F43 from the previous implementer's report, which stated that
  `Interrupt` "also arrives from a cancellation of a blocked agent, which is
  likewise recorded as a timeout" — and I recorded that as a finding **without
  tracing the path myself**. One unfiltered grep for `pending_prompt` shows four
  touch points and that cancellation is not among the recorders.

  I had already written F39's rule — *a re-run is not an investigation* — and
  then made the same class of error one level up: a plausible mechanism,
  reported confidently by an agent whose other work was excellent, propagated
  into a finding and from there into a card brief that asked for the wrong fix.
  The agent I handed it to **checked, found the premise false, and said so**
  rather than implementing what I asked. That is the second time this epic a
  delegate has corrected an instruction of mine with evidence, and both times it
  was right.

  Rules recorded in F43: when a report explains *why* something happens, that
  mechanism is a **hypothesis** until someone reads the path; and a finding
  written from a report rather than from code should say so, so the next reader
  knows what has actually been verified. The original F43 text is kept beneath
  the correction so the mistake stays legible.

- **What shipped.** A fifth `AgentApprovalOutcome::Cancelled`, recorded in
  `cancel_matching` where the parked prompt is already taken under the lock.
  `/jobs show` now distinguishes a cancelled request from a timed-out one, and
  **every resolution records exactly one outcome — five of five**, across two
  exhaustive sites:
  - `resolve_prompt`: allowed once / allowed always / denied (human answers via
    `/jobs reply`), and timed out (the block timer);
  - `cancel_matching`: cancelled, for all four cancel spellings.

  Exactly one and never two, because both sites gate on `pending_prompt.take()`
  returning `Some` — so a still-armed timer firing on a cancelled park finds
  nothing and records nothing. Pinned by a paused-clock test that cancels, then
  advances past the timeout.

- **Design notes, each decided from the code rather than from my brief.**
  - My suggested "extra parameter on `resolve_prompt`" was **impossible**: there
    is no shared call to add it to. Recording at the cancel site is what the
    code forces, and it does **not** weaken the shared-path guarantee, because
    cancellation was never on that path — it strengthens it, and the invariant is
    now pinned by test rather than assumed by construction.
  - **No machine vocabulary was added**, verified: `AgentApprovalOutcome` derives
    only `Clone, Copy, Debug, Eq, PartialEq`, has no DTO field and no `wire()`,
    and reaches machine surfaces only as a timeline entry's free text.
    `AgentApprovalKind` needs `wire()` because that kind *is* a DTO field and a
    hook variable; this outcome is not, and inventing a machine vocabulary
    nothing consumes is what **F45** forbids.
  - **One unrequested production change, reviewed and accepted:** `unblock()`
    moved one statement earlier, before the `if let` rather than after. I
    checked it is behaviour-neutral — `unblock()` only flips the phase and
    clears `waiting_for`, while the outcome's kind comes from the **taken
    prompt** rather than from thread state, and the recording has no phase guard
    — and both orderings end in the same state under one lock. Harmless and
    arguably clearer, so accepted rather than sent back.

- **Test quality worth noting:** the five new guard tests pin **whole entry
  vectors with `assert_eq!`** rather than asserting absence, which is **F41**'s
  remedy applied by default — "is not recorded as a timeout" is expressed as "is
  exactly this". The one genuine negative assertion is made non-vacuous inside
  its own test by a sibling agent whose `/jobs show` *does* print "timed out",
  from the same surface and entry type. One existing test was also found to be
  weaker than it looked — it asserted `contains("timed out")` where the new
  guard asserts the exact vector.
