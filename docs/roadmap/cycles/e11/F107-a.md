# E11 / F107-a — five test guards, and a findings entry that was wrong in three places

- **UTC start/end:** 2026-10-16T07:15Z / 2026-10-16T03:25Z
- **Branch/base:** `features/tui_herdr_improvements` / `40e376a`
- **Epic/story/card:** E11 / **F107-a**. Records **F112**. **Corrects F107 and
  retracts F80.**
- **Requirement:** none — test isolation. **No user-visible change and therefore
  no CHANGELOG entry**, deliberately.

- **The card was returned as "do not build it as scoped", and that was right.**
  The surface slot has **six production writers, every one on `run_chat`'s own
  thread**; everything off-thread only **reads**, cloning the `Arc` and dropping
  the guard before returning. One process, one terminal, one `run_chat`. So the
  global is **correct in production**, and the three refactors F107 contemplated
  — scope per test, thread it through, restructure installation — were
  **refactors of a correct global justified by a bug that cannot happen**.
  Threading it would have touched 19 call sites across three crates.

- **What shipped instead: five `#[serial_test::serial]` attributes**, no
  production change. The cause is one sentence: **`#[serial]` excludes other
  `#[serial]` tests, not plain ones**, and four `#[tokio::test]`s reach the slot
  through **production** code rather than `SurfaceProbe` — painting the attach row
  *and* installing a `BufferedSurface` over whatever is there. All 87 `#[serial]`
  tests were already mutually excluded; the gap was exclusion against tests that
  install through production. They reach it via module-local `one_read` helpers,
  **which is why a call-site grep misses them**.

- **Found with F108's instrument.** One temporary line logging
  `std::thread::current().name()`, which under `cargo test` **is the test's
  name**. The smoking gun is an agent id in the output belonging to no test that
  prints it — another test's fixture arriving through the shared slot.

- **A fifth guard, derived by reading rather than by a sighting.**
  `the_handler_byte_string_equals_the_restore_helper_output` is a non-serial
  **mutating reader** of `ALTERNATE_SCREEN_TAKEN` in the bin binary: it asserts
  the signal string equals `write_restore_sequences`' output, true only while the
  flag is `false`, and the serial fullscreen tests set it `true`. Bidirectional —
  it also *clears* the flag, so it can make a fullscreen `leave` skip its
  `ESC[?1049l`. **0 sightings in 821 runs**; the window is one synchronous
  enter→leave. Guarded anyway.

- **F112: three errors in F107, all mine.** `tui_bridge.rs:966` is `fn
  invalidate`, not the slot — the real one is `kitsu-render/src/surface.rs:162`,
  **a different crate and never a `Mutex<Option<..>>`**; I had **conflated three
  globals into one**. The "16 readers" figure counted **nine test-module readers**
  as call sites and omitted **twelve** in the actual hot path (**F74**, inside my
  own finding). And the recap test **was already `#[serial]`** when F107 was
  written — nine commits before its third sighting — so **the smaller fix I
  proposed was already in the tree**, which is why the card as scoped would have
  fixed nothing.

- **F80 retracted: it was never a flake.** The capture is a misfiled
  **failing-first** run of T3-S7a. `approval_modal` **unconditionally pushes its
  header**, so `left: []` is unreachable for it; its three tests pass an explicit
  `false` and **read no global**; and the capture's binary ran **127** tests where
  the clean runs ran **130**. I filed a card's own red run as evidence of a race
  and counted it for ten cards.

- **Acceptance:**
  ```
  cargo test -p kitsu --bins            957 passed, 0 failed
  cargo clippy --workspace --all-targets -- -D warnings   0
  150 full --bins runs, debug: ZERO sightings of the recap flake
    (vs 3 failures in 421 unguarded runs; assessor measured 0 in 400)
  ```
  **One of the 150 runs failed on a test nobody had named** —
  `subagent::tests::spawn_agent_runs_nested_loop_and_returns_only_the_child_answer`
  — which passes in isolation, carries no guard, and **does not reach the slot**,
  so it is probably a different family and is recorded as the eleventh flake,
  mechanism unknown. **My capture truncated its assertion**, which is my error:
  F39 exists because a flake without its output is a rumour.

- **The flake ledger: ten became seven**, wrong in **both directions at once** —
  it carried three entries that were never flakes and missed one that had been
  failing all along. That is the argument for treating it as evidence rather than
  a count.

- **The lesson, about findings files rather than mutexes.** **F91** says a wrong
  entry in this file is worse than a wrong brief, because a brief gets questioned
  and this file gets **quoted**. F91 was about someone else's error travelling
  four hops. **F107 was mine and travelled further**: it set a card's scope, was
  cited in four cycle records, counted a non-existent flake family for ten cards,
  and I recommended it as *"the most valuable card left"* one commit ago. The rule
  that would have caught it is the one I already apply to code — **an entry
  asserting "X already does Y" needs the line that shows it.** F107 asserted five
  such things; I had re-read the line for none.
