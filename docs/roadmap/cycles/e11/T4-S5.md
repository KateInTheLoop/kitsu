# E11 / T4-S5 — the filter line, and a refusal the user could not have seen

- **UTC start/end:** 2026-10-15T06:30Z / 2026-10-15T10:15Z
- **Branch/base:** `features/tui_herdr_improvements` / `939a10b`
- **Epic/story/card:** E11 / T4-S5. **The last key A3 listed with no binding.**
- **Requirement:** **A3**, amended with four decisions. Records **F70**,
  **F71**.

- **What shipped.** `/` opens a filter line over `kitsu-editor`:
  `s:<state> n:<text> o:<text> p:<profile>`, each term confined to its own
  field. T4-S1 had built `AgentFilter` and its parser four cards earlier; I
  verified it was **parsed but never applied** in production, and this card
  wired it.

- **The card's real content is a safety property, not a view feature.** The
  selection is keyed on an agent id, and a filter **hides rows without the
  agents going away** — so `AgentSelection::sync` is handed the **filtered**
  rows. Handed the registry's rows it would leave the selection on a **hidden**
  agent, and the dispatch would then let `x`, `r`, `n` or `p` act on an agent
  **not on screen**: the **F68** family exactly, which cost this epic a
  rejection.

  Pinned: a filter hiding the selected agent moves the selection to a visible
  row; a filter matching nothing leaves **no** selection, so `x` reports the
  no-selection line rather than stopping the agent that *used* to be selected.
  **Clearing the filter restores nothing** — a remembered selection is hidden
  state steering a destructive key, the same hazard with one more step. There is
  no remembered selection anywhere in the implementation, only the per-repaint
  sync against the filtered list.

  **Applied in exactly one place** (`overlay_visible_rows`), which both the loop
  and the test harness call — verified by grep: one call site, the other two hits
  being a comment and an unrelated doc string about session filtering.

- **F71 — the finding worth keeping, caught beyond the brief.** The card decided
  an invalid term is refused with the parser's own message. The obvious
  implementation puts it in `state.report`, **which the tests collect and
  assert, and which would have passed.** But the frame chain puts the open line
  innermost, so a report row painted under the row list is **not on screen while
  the line is open**: the refusal would have been **observable to the test and
  invisible to the user**, and the card's own decision would have shipped as a
  message nobody could read, with a green suite.

  **The test and the user were reading different surfaces, and only one of them
  is the product.** A test that asserts a message exists has not asserted that
  the message is on screen. The fix paints the refusal **on the filter frame**,
  and `/` clears a stale report on open so the frame only shows a refusal of
  what was typed into it.

- **The input lives in the editor, decided by evidence rather than taste.**
  `OverlayKey::Char` is **ASCII-only by construction**, and `n:café` is a
  plausible **and legal** filter. Confirming it turned up **F70**: the `n` key
  silently drops non-ASCII bytes the registry accepts — typing `n:café`
  renamed an agent to `:caf`. **Recorded, carded, and deliberately not fixed
  here.** The filter line instead joins `s`'s byte bypass, so it inherits
  non-ASCII, split multi-byte characters across reads, and F68's paste rule in
  the same place as every other text field.

  **F45 honoured on the way:** rather than a second line editor, the editor
  wrapper was extracted — `SteerLine` now delegates to a shared `OverlayLine`,
  and the two frames share one echo/caret/windowing routine. All pre-existing
  steer tests pass untouched.
