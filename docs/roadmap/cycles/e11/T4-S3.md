# E11 / T4-S3 — peek, and a premise of mine that was false

- **UTC start/end:** 2026-10-15T01:35Z / 2026-10-15T06:04Z
- **Branch/base:** `features/tui_herdr_improvements` / `e791fa2`
- **Epic/story/card:** E11 / T4-S3.
- **Requirement:** **A4** shown satisfied by construction; **A7** clarified.
  Records **F64**.

- **What shipped.** `Space` peeks the selected agent in the overlay: the bounded
  redacted timeline `/jobs show` prints, the permission kind it waits on if
  blocked, and its result or failure if finished — and peeking takes custody of
  the result exactly as `/jobs show` does.

- **My brief's premise was false, and the plan row's acceptance with it (F64).**
  I wrote that the exit guard "refuses to quit while a finished agent's result is
  unobserved", repeating the row's *"unviewed failed agent still refuses"*.
  **Verified false:** the only quit refusal counts `Running | Blocked`, so a
  finished-but-unviewed agent does not block `/quit` at all. Unviewed results
  are **surfaced** on the way out.

  The test author **stopped rather than writing the test**, recognising that
  asserting a refusal would contradict the quit path and the exit tests that pass
  today — an **F61**-shaped conflict. It pinned the real round trip instead: a
  peeked result is not surfaced at exit, an unviewed one still is.

  **This is my second instance of the same error** (the first was **F43**), and
  the useful part is why it is easy: **the codebase itself calls this "the exit
  guard on unviewed results"**, in a doc comment explaining that `/jobs explain`
  avoids acknowledging so it "cannot take custody of its result and defeat the
  exit guard on unviewed results". The **name** is accurate and long-standing;
  only the mechanism differs from what the name implies. A well-named mechanism
  invites you to assume its implementation, and nothing in the row or that
  comment would have corrected the inference.

- **A4 is satisfied by construction, and the card proved it rather than adding a
  filter.** The snapshot's `waiting_for` is a **unit enum**, so a path is not
  representable; timeline text is redacted at the source and the DTO's
  `validate` **rejects** anything not already redacted; approval entries carry a
  kind only. So rendering the same snapshot satisfies "never show tool
  arguments".

  The implementation therefore **reused `/jobs show`'s own renderers** —
  `format_agent_thread`, `pending_approval_request`, `peek_result`,
  `sanitize_terminal_text` — and copied the `peek_result` → `acknowledge_result`
  order and the `phase != Running` gate **from the `show` arm**, so the two
  surfaces cannot drift. The only new rendering is the panel frame.

  **And the absence assertion is not a bare ban:** a sibling agent in the same
  registry has a *result* containing a path, and its panel must **contain** it —
  because redaction deliberately leaves paths untouched. A panel that scrubbed
  paths wholesale fails there before any ban is reached. A later reader must not
  add a scrubbing filter.

- **The over-acknowledgement direction is pinned, which is the one that
  matters.** Peek is not read-only: it changes whether a result is reprinted at
  exit. So the tests pin that **opening the view and repainting its rows
  acknowledge nothing**, with a peek afterwards as the positive control, and that
  **peeking a blocked agent acknowledges nothing** (`acknowledge_result` returns
  `NotReady` for `Unavailable` without mutating). If merely moving over a row
  took custody, the guard would stop meaning anything — and the implementer left
  a note for whoever adds selection state saying exactly that.

- **A key that worked but was not advertised — fixed rather than deferred.** The
  overlay's help listed only `?` and `esc`; `Space` worked and was
  undiscoverable, which by this project's own standard (**F38**: a command that
  works but cannot be found is half-shipped) is a defect. I added it to the help.
  The reasoning for doing it here rather than waiting for T4-S10's single
  bindings table: **that list is already a literal of two, so a correct third
  entry is not new duplication** — whereas a working key missing from the help is
  a defect a user meets. T4-S10 still replaces the whole list.
