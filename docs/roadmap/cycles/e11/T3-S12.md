# E11 / T3-S12 — reduced motion reaches the viewport, and the frame budget becomes real

- **UTC start/end:** 2026-10-14T21:55Z / 2026-10-15T03:08Z
- **Branch/base:** `features/tui_herdr_improvements` / `6d22d79`
- **Epic/story/card:** E11 / T3-S12.
- **Requirement:** **N3** and **N9**, both **amended**. Records F39's fourth
  occurrence.

- **What shipped.** `--reduced-motion` now reaches the inline viewport: the
  status row stops repainting because the clock moved, while still updating on a
  real state change. And the **60 fps budget is enforced in the painter**, where
  it can be, instead of being inherited from how often one caller happens to
  ask.

- **Both defects were measured, not inferred.** With reduced motion in force and
  nothing moving but the clock, the painter emitted a full row a second later —
  precisely N9's "periodic age refresh". And a loop moving a single
  **non-elapsed** field defeated the byte-identity dedupe completely, reaching
  roughly **109 000 fps in debug and 400 000 in release**. After the fix both
  profiles sit flat at **60**, which is the right shape: a budget that varies by
  build profile is not a budget.

- **"≤ 60 fps" was accidental, and the risk was already live.** It held only
  because the input tick sleeps 50 ms. This epic had **already added a second
  author of that row** (`clear_approval_modal`, T3-S7a), so the property was one
  caller away from being false. Enforcing it in the painter is what makes it a
  property of the row rather than of its callers.

- **The subtle part is how the budget keeps the last frame.** Coalescing means
  *collapse the intermediates and keep the latest*, never *discard what arrived
  during the window* — and the test was built to catch the difference, by
  setting the queue depth to 7 after the churn and requiring `[7 queued]` on
  screen. A naive rate limiter fails that.

  The implementation records the dedupe key **only when it actually paints**, so
  a suppressed call consumes nothing and the next call past the window
  recomposes from the fields **as they stand then**. Nothing is latched, nothing
  is queued, and no timer thread exists. The ordering is deliberate too: dedupe
  **before** the window, so an unchanged row still costs zero bytes and does not
  burn a frame.

- **Reduced motion draws its line in the dedupe key, not in what is painted —
  which is better than what I asked for.** The key is the row recomposed with
  `elapsed: None`, so a clock-only change compares equal and no paint follows,
  while every other field still changes the key. **The bytes written are always
  the real row including elapsed**, so when a state change does paint, the age
  shown is current rather than stale by construction. *Reduced motion removes
  the periodic refresh, not the field.*

  **The line itself matters more than the mechanism.** N9 names spinner
  animation, counter flashes and periodic age refresh — not state. Freezing the
  queue tag and the ambient agent tag to make the row quiet would **hide a
  blocked agent**, defeating the affordance R5 and A8 exist for. The test
  carries that as a control: a queue change must still paint, and with motion on
  the same wait must paint, so "nothing emitted" cannot mean "nothing wired".

- **Synchronized output is deferred, and I accepted the argument rather than the
  absence.** Mode 2026 can only be detected in band with DECRQM and **reading
  the reply on stdin**, which the input loop owns in raw mode while also serving
  approval reads (T3-S7b). Waiting for a report that may never come is a
  **hang**; a timeout is a **sleep on the first frame**; emitting blind leaves
  visible garbage on terminals that do not implement it. The row is one line, so
  tearing is not a live defect. **Two tests pin that the bytes are never
  emitted**, each documenting what to write when a probe exists — a deferral
  with a guard is worth more than a deferral in a comment.

- **Two points of craft worth recording.** The test author **verified its own
  assertions were satisfiable** before handing over — writing a throwaway
  implementation, watching all three go green, then removing only the rate gate
  to confirm the budget test fails independently, then reverting. That is
  **F58**'s lesson applied without being asked twice. And the implementer
  **exported the existing `reduced_motion_mode`** rather than adding an
  accessor, reasoning that a second entry point would be a second definition of
  "reduced motion" that could drift from the one the spinner uses — this epic's
  one-source discipline, applied unprompted.

- **F39's fourth occurrence, and the shape is now confirmed.** The same
  byte-identity test failed once under full-workspace load, and this time with
  the detail: the scripted run carried `joining them` and `joined 1 background
  agent` lines the JSONL run did not, because under load the detached agent had

  it. **It is a test synchronisation defect, not a product one**, and the fix is
  now specific — join deterministically before comparing, or exclude the join
  narration. The implementer diagnosed rather than re-running, which is why the
  detail exists.
