# E11 / F77 + F79 — a command that did nothing, and the third consumer that proved the pattern

- **UTC start/end:** 2026-10-15T10:05Z / 2026-10-15T13:42Z
- **Branch/base:** `features/tui_herdr_improvements` / `23e21cd`
- **Epic/story/card:** E11 / **F77**, with **F79** folded in.
- **Requirement:** **A5** / **§4.5**, amended. Records F79's resolution.

- **What shipped.** `/detach` works: it answers `detached from agent N; it keeps
  running`, records `{"kind":"detach","agent":N}`, and with nothing attached
  answers `not attached to a background agent` as an error. **And attaching now
  works from every route into the view** — the chord, the double `←`, and
  `/jobs view`.

- **The division of feedback, decided here:** **the two keys are silent and the
  command answers.** `←` and `Ctrl+X d` deliver feedback where the eye already
  is — the prompt label changing under the caret — while a submitted line moves
  the eye into the scroll region, which has somewhere to put a reply (T2-S5b).
  The success line repeats the "stops nothing" clause because it is **the last
  moment a user who read `/detach` as "cancel the agent" can be told otherwise.**

- **F79, folded in rather than carded.** `/jobs view` kept only the overlay's
  `.shown` and **threw the attachment away**, so attaching from that route
  silently attached to nothing. Same mechanism, same seam — the `&mut
  Option<u64>` F77 needed is exactly what that arm needed — and leaving it would
  have shipped "three ways to return" **conditional on how you attached**, with
  last card's corrected docs still conditionally false.

  **It was F75 word for word in the third consumer of the same exit value.** F75
  was the first (the binding did not exist), F77 the second (an arm predating the
  feature), F79 the third. **The lesson, sharper than the two I drew before:
  when a function starts returning something new, every caller is a suspect, and
  callers are enumerable.** `run_agent_view_overlay` changed from `-> bool` to
  `-> AgentViewExit` in T4-S6a's rework; that change came with a complete list of
  two places to check, and nobody checked the list. **A type change is the
  cheapest possible audit trigger and it was free.**

- **My brief was wrong again (the tenth mechanism correction).** I wrote that the
  `/jobs view` arm is in `handle_slash`; it is in `handle_jobs_command`, which
  has **five existing unit-test call sites**. I had caught the ninth myself on
  this same card — the previous report's non-existent `handle_slash_command` —
  so both of this card's stated mechanisms were wrong and both were corrected by
  reading.

- **A test-only shim I removed on review.** Faced with five test call sites it
  was forbidden to edit, the implementer kept the three-argument name as a
  `#[cfg(test)]` shim and **said so plainly**. I removed it: a `cfg(test)`
  function **shadowing a production name** means the tests call something
  production never calls, which is **F69** exactly. The five sites now name the
  production function and pass `&mut None` explicitly, which **documents** that
  they do not drive the view instead of hiding it. Five one-line edits, no
  assertion touched.

- **The seam the implementer added is the right kind.** `run_agent_view_overlay`
  declines outside inline mode on a tty, so the arm **cannot be entered from a
  test** — which is exactly why the discarded attachment survived review. It
  extracted `apply_jobs_view_exit(&exit, attached) -> bool`: F79's one call plus
  the `shown` the text-deck fallback needs, in one reachable place. Making the
  unreachable thing reachable is **F71**'s and **F75**'s lesson applied before
  the fact.

- **Both traps re-proved by prototype** — the fourth card to use this method. A
  body applying the exit to a **local copy** leaves `shown == true` and still
  fails on the painted row; `apply_detach_command` clearing a copy returns
  `Detached(1)` and still fails. Both reverted from byte copies. **No fourth
  consumer**, checked because the list is enumerable.
