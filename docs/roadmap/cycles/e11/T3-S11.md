- **F59 — the row's premise was wrong, and the correction is reusable.** The row
  says the check needs "(no linker needed)". True as far as it goes —
  `cargo check` does not link — but the check dies **earlier**, in a build
  script:

  ```
  error: failed to run custom build command for `ring v0.17.14`
    CC_x86_64-pc-windows-gnu = None
  ```

  `ring` compiles C and needs a MinGW cross-compiler for the target, which is
  not installed here. **`cargo check` skips linking, not dependencies' build
  scripts** — those still run, and a build script is arbitrary code with
  arbitrary toolchain needs. The lesson: **a cross-target check is only as
  portable as the least portable build script in the tree.**

  Worth noting *where* the blocker is: `ring` arrives through
  `kitsu-providers`, i.e. **TLS**, not through anything the terminal work
  touches. "The Windows check fails" would have been a misleading summary; "a
  TLS dependency needs a C cross-compiler, and every terminal crate is clean" is
  the useful one.

- **What I deliberately did NOT do.** The row also asks to "remove the
  `cfg(unix)` gate where it compiles" — **4** gates in `tui_bridge.rs` and
  **85** in `main.rs`. Both files live in the crate that **cannot be checked
  here**, so narrowing a platform gate would mean guessing which lines compile
  on Windows with no compiler to prove it. That is precisely the kind of
  unverified change this epic has refused repeatedly, so it is handed over
  rather than attempted. `viewport.rs` has **zero** such gates already, which is
  consistent with it checking clean.

- **Q1 remains open and remains a human task.** The checklist at
  `terminal-matrix.md` was written for a person at real terminals, and **F13**
  records why automation cannot substitute: the `vt100` emulator the suite uses
  pushes a row to scrollback only when **no** scroll region is active, and the
  inline viewport always sets one — so region-scrolled rows are discarded **by
  construction**. A test pins that limitation negatively, so it lives in code
  rather than folklore. The VT specification does not say what scrollback should
  do inside a scroll region, which is exactly why each terminal differs and why
  it must be measured rather than reasoned about.

  **It gates making `inline` a default rather than an opt-in**, and nothing in
  this repository can discharge it.
