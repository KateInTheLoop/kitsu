# E11 / T2-S6 — the approval record, argument-free by construction

- **UTC start/end:** 2026-10-14T10:40Z / 2026-10-14T12:11Z
- **Branch/base:** `features/tui_herdr_improvements` / `13f12ea`
- **Epic/story/card:** E11 / T2-S6.
- **Requirement:** **N8**, which this card **amends**. Records **F40**, **F41**,
  **F42**, **F43**.

- **What shipped.** The bounded agent timeline now records each permission a
  background agent asked for and how it ended — allowed once, allowed always,
  denied, or timed out — surfaced in `/jobs show` and, for a pending request,
  on `/jobs explain`'s `waiting on:` line in preference to the last tool
  activity. Before this card, an answered agent showed no trace of ever having
  asked.

- **The security property is the card (F40), and it is structural rather than
  filtered.** `docs/functionality.md` states an absolute: *tool
  arguments/output and partial model bodies are never copied into that
  inspection record*. An approval entry is the first thing in this epic that
  collides with it, because a permission request **is** a tool plus its
  arguments.

  Two facts, both established by reading rather than assumed:
  1. **Today's protection was an accident.** `prompt_sender` destructured only
     `agent_id` and `reply`; `request.payload` was **dropped unread**. No
     argument could reach the timeline because the data never arrived — and this
     card is precisely the reason to plumb it deeper.
  2. **Redaction would not have caught a leak.** A test now pins that
     `sanitize_and_redact_text` leaves filesystem paths, `rm -rf /work/tmp` and
     URL paths **completely untouched**; it strips terminal controls and
     credential forms only. Redaction here answers *"is this a secret?"*, not
     *"is this private?"* — and the snapshot validator uses the same function,
     so an entry carrying a path would have passed validation on its way to
     `/jobs show`, `/jobs explain` and the JSONL snapshot.

  So the entry carries a **kind and nothing else**. The payload becomes an
  `AgentApprovalKind` at one boundary (`subagent.rs`, one line before
  `park_prompt`) and no argument travels further; the kind is a **unit enum with
  no argument-bearing field**, so a future change cannot carry a path into an
  entry **without altering a public type** — a review-visible act rather than a
  silent one. Same move as T2-S3's exhaustive `match`: make the compiler the
  thing that notices.

- **Two traps the test author found by reading, before either was paid for:**
  `record_runtime_event` returns early unless the phase is `Running`, so
  routing approval recording through it would have recorded **nothing** — a park
  *is* the `Blocked` phase; and the timeout path had to record too, since it is
  the one case with **no human present**, which is why `resolve_prompt` (shared
  by `answer()` and the B3 timer) is where the outcome is written.

- **No structured-surface work was needed, and that was checked rather than
  hoped.** The timeline is the only route to the JSON surface and it is already
  wired: `/jobs show --json` and `/jobs explain --json` embed the whole
  snapshot DTO, whose `validate` already enforces the redaction check and the
  byte/event budget. Approval entries inherit all of it, including the bounded
  accounting — pinned at 128 entries under tiny limits.

- **Review findings and fixes:**
  1. **F41 — a substring ban that constrained the product instead of protecting
     it.** The argv-absence sweep forbade the bare string `"rm"` anywhere in the
     snapshot, and the implementer's first attempt failed it **on the word
     "permission"**. Nothing had leaked; the assertion cannot tell the command
     `rm` from the middle of an English word, and equally forbids *format*,
     *confirm* and *firmware*. The implementer worked around it with wording that
     avoids the substring and **flagged it rather than hiding it** — but that
     left user-visible wording constrained by an accident of a test.

     **Fixed at review by making the assertion stronger, not weaker:** the entry
     text is pinned with `assert_eq!` to its exact expected string, which no
     argument can hide inside whatever the argv happened to be — a property a
     substring ban cannot express. The snapshot sweep stays, with tokens
     distinctive enough that only a real leak matches. **Verified by injecting
     `/work/tmp` into the entry text and watching it fail**, then reverting.
     General rule recorded: to assert something private is absent, pin what the
     output *is*, not a list of things it is not.
  2. **F42 — I destroyed this card's uncommitted work, and the history passed
     through a broken state.** Reverting that injected leak with
     `git checkout crates/kitsu/src/subagent/thread.rs` reverted the file to
     HEAD, because nothing in it was staged — wiping both agents' T2-S6 work
     there (enums, stubs, six tests, wiring) and leaving 21 compile errors in the
     two files that survived.

     Recovery was **complete rather than reconstructive**: both agents still held
     their contributions and restored them in sequence — the test author its
     stubs and tests (deliberately still no-ops, so the TDD record stayed
     honest), then the implementer its wiring — so nothing was rewritten from my
     memory of a report. The cost was time, not work. The rules: never
     `git checkout <path>` on a file holding uncommitted work; check
     `git diff --numstat` before any destructive git operation on a path — the
     exact discipline applied all session to the maintainer's `fs.rs`, which
     stayed at `54 20` throughout; and run verification experiments in a
     throwaway copy, never in the file under review.
  3. **F43 — a defect found at review and deliberately NOT fixed here.**
     Cancelling a blocked agent resolves through the same path as the timeout,
     carrying the same `Decision::Interrupt`, so a human cancellation is
     recorded as *"approval to write a file timed out"*. For a card whose whole
     purpose is a truthful record that is a correctness defect, not a cosmetic
     one, and no test pins the case either way — which is why it passed green.
     It is not a one-liner: the two cases are indistinguishable at the recording
     site, so the fix needs a fifth outcome plus a way to tell the caller's
     intent apart, or recording at the two call sites instead of the shared one.
     Carried as its own small card, which should also pin the case nothing
     covers today.
