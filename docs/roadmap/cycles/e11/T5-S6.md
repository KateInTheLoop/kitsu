# E11 / T5-S6 — `agent_wait`, and a token budget that said no

- **UTC start/end:** 2026-10-16T11:20Z / 2026-10-16T05:52Z
- **Branch/base:** `features/tui_herdr_improvements` / `2dee9a2`
- **Epic/story/card:** E11 / **T5-S6**. Records **F117**. **Requirement H5 is now
  shipped** and amended with what it left open.

- **What shipped.** `agent_wait(id, until, timeout_secs)` — a foreground model can
  block on one background agent instead of polling.

- **`done` is the terminal predicate, not the `Done` variant.** The test author
  found this and it is the card's real design decision: `terminal` is
  `!matches!(phase, Running | Blocked)`, so a **failed** or **cancelled** agent
  satisfies a `done` wait. Matching the variant alone would have burned the whole
  timeout waiting for a state that can never arrive (**F84/F75**), and the
  mutation proving it fails with `timed out after 600s … agent #1 failed: boom`.
  The same reasoning gives the converse for free: waiting for `blocked` on an
  agent that has gone terminal is unreachable, so it returns **at once** rather
  than holding the round open — while a `done` wait on a *parked* agent does run
  its timeout out, because `blocked` is non-terminal and the agent is still live.

- **The author refused to fake the one assertion they could not honestly make.**
  H5 says the tool is bounded by `--max-rounds` *and* its own timeout. `max_rounds`
  lives only on `AgentConfig` and is enforced only in the orchestrator loop; a tool
  handler cannot see it. So the honest reading is a **conjunction of two
  independent bounds** — the timeout bounds one call, the round cap bounds how
  many — and any test in the tool's own file would assert **the absence of a
  parameter**, which is structural and vacuous. They wrote none and said so. The
  round cap is already covered by `kitsu-core`'s own test.

- **The budget test has a positive control**, which is what keeps it honest: it
  builds a real `SpawnBudget::new(1)`, spends it, **asserts that a second spawn
  fails**, and only then asserts the wait works and `used()` is unchanged. Without
  that control it would pass against a budget that was never exhausted.

- **Timing was designed away, not tolerated.** `#[tokio::test(start_paused = true)]`
  — already used **21 times** in this file — so elapsed assertions are **exact**
  (`== ZERO`, `== 90s`) with no tolerance windows and no `sleep`, and state changes
  go through the registry's own `subscribe()` seam, whose doc comment is
  *"without a check-then-sleep race"*. **25 consecutive identical runs.** In a
  suite with seven open flakes, a wall-clock test would have been the twelfth.

- **Twelve mutations, each failing with its own message**, bidirectional on both
  state pairs — including that an **unclamped `i64::MAX` timeout panics in
  `std::time`** on deadline overflow, which is why the 30-minute ceiling exists.
  The author also reported two first attempts as **invalid rather than counting
  them**, and reported that one STILL-PASSES was their own mutation's fault,
  because the unknown-id path has **two** redundant guards and they had broken one.

- **F117 — registering the tool broke a knife-edge CLI test, and the fix was
  production code.** `test_context_command_surfaces_window_runtime_evidence` drives
  an **8192-token window with a ~23k-character prompt and clears its trim target by
  about 90 tokens**. The first descriptor cost **217** tokens of schema and put the
  protected prompt **21 over**; the binary exited 1. The implementer **trimmed the
  descriptor** — no prose on `until`, since the closed `enum` already says it —
  down to **148** tokens, and touched no test. That is the right call: the test was
  not wrong, and "fixing" its window would have destroyed a real budget guard to
  make room for prose.

  **But it is a tripwire and is carded.** Any next tool in the non-lean tier will
  break it again, at any size, and because it asserts a **startup exit code** the
  failure says nothing about why — the cause was only found by reproducing the
  binary's stderr by hand. And H5's real cost is **151 tokens, not 148**:
  registering the tool also grew the base prompt by 3, because the name reaches the
  system prompt as well as the schema list.
