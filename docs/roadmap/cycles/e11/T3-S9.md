# E11 / T3-S9 — the renderer switches without losing the conversation

- **UTC start/end:** 2026-10-14T20:05Z / 2026-10-15T01:26Z
- **Branch/base:** `features/tui_herdr_improvements` / `e2654f4`
- **Epic/story/card:** E11 / T3-S9.
- **Requirement:** **R2**, which this card **completes**. Records **F57** and
  **F58**.

- **What shipped.** `/tui [classic|inline]` switches the renderer between
  turns without losing the conversation; bare `/tui` reports the renderer
  actually running; `fullscreen` is refused by name until T5; and `/tui` during
  a turn is refused rather than queued.

- **The acceptance assertion is the best-constructed one in this milestone.**
  R2's gate is "without losing the conversation", which a weak test would read
  as "the command was accepted". Instead the author chose a marker — a
  `/theme` rejection line — on four verified properties: emitted by the binary,
  unique in the whole stream, needing no network or turn, and **exactly 76
  columns, so one physical row** at 80 columns where the emulator has **zero
  scrollback** and 24 rows is the entire budget. It verified those bytes against
  a real run rather than predicting them.

  Then it counted each marker **twice, in two places**, and said what each
  catches: `raw_count == 1` catches a switch that **replays** scrollback
  (counts 2+), and the on-screen count catches one that **cleared** the screen
  or scrolled the region away (counts 0). *"Neither count alone is
  sufficient."* Plus a third assertion that the three markers appear **in
  printed order down the screen**, so what survives is a continuing conversation
  rather than three fragments. Markers straddle both switches, so "content
  before survives" and "content after appears" are pinned in one session in both
  directions.

- **F57 — the blind spot in the fix this whole epic converged on.** Six cards
  concluded "one source, many readers" defeats drift. The author found where
  that stops: it added a registry entry with **no dispatch arm** and ran
  everything — the binary prints `unknown command: /tui - did you mean /quit?`
  and **all 824 binary and 245 CLI tests pass**. Nothing asserted that a
  registered command is *reachable*.

  And the second failure mode is worse: the mid-turn dispatcher's default
  fall-through is `queue.enqueue(line)`, so an unhandled slash command typed
  during a turn is **sent to the model as a prompt**.

  **The F2-style guard cannot be copied here, and the reason is that the fix
  worked too well.** `closest_jobs_subcommand` kept its own hardcoded table, so
  comparing it with the dispatcher catches drift. `closest_slash_command`
  **reads the registry**, so the analogous sweep compares the registry with
  itself and **passes vacuously**. The rule recorded: *a single source of truth
  guarantees readers agree with it; it guarantees nothing about whether anyone
  acts on what they read.* Reachability is a different property from consistency
  and needs its own test — a follow-up worth taking for all 54 commands.

- **F58 — an unsatisfiable test nearly changed the product, and I reverted it.**
  One assertion required the palette to contain `" /tui [classic|inline]"` at
  width 80 — but at that width the palette renders the **wide** branch (name and
  description); the asserted shape belongs to the **compact** branch, used only
  below 40 columns. **No registry entry could satisfy it.**

  The implementer was forbidden from editing tests, so the only path open was to
  change the product — and it did, carefully, making the wide branch show syntax
  when it fits. That **altered the palette for every short-argument command**
  (`/model <name>`, `/theme [name]`, `/usage [session]`, `/undo [id]`) in a
  card about a renderer switch. **It flagged the deviation instead of burying
  it**, which is the only reason this is a finding rather than a silent
  regression.

  I reverted the palette to byte-for-byte what it was, removed the now-unused
  constant, and corrected the assertion to the wide branch's real shape. The
  test's intent is served identically.

  **Why it earns its own finding:** this project has seven findings about
  **vacuous** assertions. This is the mirror — an assertion that can never
  *pass*. Same cause (an expectation written from a mental model of the output
  instead of from the output), opposite failure, and the unsatisfiable one is
  **more dangerous in a TDD loop**, because the implementer's job is to make it
  pass and the test *is* the specification. The author had derived its transcript
  markers from a real sample and then not done so for this one line.

- **Two traps found by reading and honoured.** `status_source` was built once
  outside the loop, so a re-install that forgot to republish it would leave the
  pinned row showing `install`'s static `"kitsu"` fallback — it is now
  published per **install**, and a test asserts the live model returns after
  switching back. And the `Once`-gated signal restore is sound across repeated
  install/teardown because the handler holds **no viewport handle** — only two
  atomics and a `const` — which I verified independently. Its consequence is
  documented in R2: byte-identity for classic is scoped to sessions that never
  switched.

- **The teardown runs mid-session for the first time, through the existing
  path.** The guard became a reassignable binding at the idle-prompt seam;
  `None` *is* the teardown, in its established order, with no second path
  hand-rolled. A new `SlashResult` variant carries the request out of the
  dispatcher, which cannot see the guard.
