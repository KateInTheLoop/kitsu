- **UTC start/end:** 2026-10-15T12:00Z / 2026-10-15T14:47Z

- **What shipped.** `+` opens the view's **fourth** edited line: a task for the
  default profile, or `@<profile> <task>`. Admitted by `AgentRegistryLimits`,
  **not** the model's per-turn `SpawnBudget`. Refusals are painted on the
  dispatch frame and leave the task in the line. A dispatch does not move the
  selection.

- **A6 was wrong twice, and the requirement now says so.** It calls the surface a
  *composer* — the view has **modal edited lines**, not a composer — and it names
  **no key** while A3's list was full. So a key was invented here, which the
  requirement should record rather than leave looking pre-ordained.

- **The key was chosen for a property, not for taste.** `+` is `0x2b`,
  **outside the CSI final-byte range `0x40..=0x7e`** — the property `/` was
  chosen for, and one `r`/`s`/`n`/`p`/`x` do **not** have. I verified it.
  **This is the first key in this epic picked with F65's lesson in hand rather
  than after a defect taught it** (*an arrow key is not one byte* cost a card when
  the overlay's close key ate the first arrow). Exported as `DISPATCH_KEY` so the
  help row, the overlay arm and the tests read one letter and **no test spells the
  character.**

- **The negative claim got its positive form.** "The `SpawnBudget` is not
  consulted" cannot be tested by not mentioning it. The test shares **one**
  budget and **one** registry: the model's spawn spends the turn's only credit,
  **the same handler is then refused** — the control proving the state really does
  refuse a model — the view's dispatch **succeeds** in that state, and the budget
  is still `used() == 1`.

  The author enumerated **all twelve** `SpawnBudget` references and found **every
  consumer is a model-facing tool family calling `admit` as its first act**, so
  A6 is satisfied by **not plumbing it**: `view_dispatcher`'s signature is
  `spawn_agent_bg_tool_with_binder`'s minus the budget. Recorded in A6 so nobody
  "fixes" the omission for consistency later.

- **The card's likely defect was pre-empted, not caught by me.** The test author
  applied **F79**'s rule unprompted: `run_agent_view_overlay` has **two**
  callers, so it wrote that the dispatcher must reach **both** "or the view starts
  agents on one route and silently cannot on the other" — which is **exactly
  F77**, one card earlier, where `/jobs view` discarded the attachment while the
  chord route worked. I passed the enumeration to the implementer as a question it
  had to answer.

  The implementer threaded it explicitly as a parameter and built it
  **unconditionally** — not gated on `interactive`, `no_tools` or `spawn_cap` —
  with the reason stated: *a gate one route could satisfy and the other not is the
  F77/F79 shape*. **That is the finding being used as a design constraint rather
  than a post-mortem.**

- **The seam, and the alternative correctly rejected.** The dispatcher is a value
  on `OverlayState`, threaded from where the binder and catalog exist. The
  implementer weighed a process-level `OnceLock` global — zero plumbing, no test
  call site moved — and rejected it. **Right call:** a process-global dispatcher
  is hidden coupling reachable from anywhere, which is the shape **F75** and
  **F79** are about, and it would have made "which route can dispatch?"
  unanswerable by reading a signature.

- **Five pre-existing test call sites moved**, by adding a trailing `None` to a
  signature change. The implementer flagged it with the alternative rather than
  doing it quietly. Verified: the diff adds **only** `, None` — **zero** removed
  assertions or test attributes.
