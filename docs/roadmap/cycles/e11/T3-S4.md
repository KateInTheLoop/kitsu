# E11 / T3-S4 — the card that needed no code, and said so with evidence

- **UTC start/end:** 2026-10-14T14:45Z / 2026-10-14T15:51Z
- **Branch/base:** `features/tui_herdr_improvements` / `11cf2d1`
- **Epic/story/card:** E11 / T3-S4.
- **Requirement:** **R4**'s history gate. **Amends** design §4.3 and the plan
  row. Records **F49** and a second occurrence of **F39**.

- **Outcome: two tests, a plan amendment, and no production code** — and that is
  the correct result, not a shortfall.

- **What the plan asked for, and why it would have made the product worse.** The
  row said the TUI composer should "load/save the rustyline history file
  format". Taken literally that means a **second parser for a format rustyline
  owns** and a **second writer competing for one file on disk** — the exact
  failure mode T3-S3 had just established against in this very subsystem ("the
  trait is a seam, not a source"), with **F2**, **F38** and **F45** behind it.

  I briefed the card to settle this by reading first, and said explicitly that
  "nothing to build, here is the test that proves it, and the plan should be
  amended" was a perfectly good and possibly correct outcome. It was.

- **What the reading established**, every claim with a code path:
  rustyline loads the file; the inline reader is handed a **snapshot** of its
  entries, taken **inside the per-iteration read** so it is fresh every turn;
  every submitted line is recorded on the path **common to both readers**,
  outside any branch on which reader produced it; rustyline saves the file. The
  word "history" appears **nowhere** in `kitsu-tui`, and the walk itself lives in
  `kitsu-editor` over a `Vec` it is handed. One implementation, one file owner.

  Order, de-duplication and blank handling were checked **against rustyline
  14.0.0's own source** rather than assumed: `iter()` is oldest-first and both
  walks take the newest on the first ↑; the dedup policy is rustyline's default
  `IgnoreConsecutive`, which kitsu does not override and the editor matches;
  blank lines never reach either walk. The one divergence that would otherwise
  exist — the first ↑ — was already closed deliberately, with a comment saying
  why.

- **The two tests the card names now exist and pass**, which is the point: the
  sharing is pinned, so a future change that forks it fails. The round-trip test
  uses a **real fixture file on disk** exercising the `#V2` header, an escaped
  line feed, an escaped backslash and a blank line, and pins the **whole saved
  file text** byte-for-byte in both directions (**F41** — what the output *is*,
  not a substring). The agreement assertions are non-vacuous by construction:
  the snapshot is asserted equal to a named non-empty list **before** any
  comparison, both walks are checked against a spelled-out expected sequence
  **before** being compared to each other, and the entries enter through
  production's own `History::add` under a `Config` built as production builds
  it — so the de-duplication under test is the real policy, not a stub's.

- **Two latent risks found on the way, correctly scoped out of this card:**
  1. **A dropped cargo feature would turn a tolerated error into a panic.**
     `DefaultHistory` is `FileHistory` only because `with-file-history` is a
     **default** feature; `MemHistory`'s `save`/`load` are `unimplemented!()`.
     So `let _ = rl.load_history(&path)` — written to tolerate a missing file —
     would **panic** if that feature were ever disabled, including by someone
     adding `default-features = false` for an unrelated reason. The `let _ =`
     makes it look safe. Recorded in **F49** as worth a compile-time assertion.
  2. **↑ on a multi-line draft diverges.** Classic binds ↑ to
     `LineUpOrPreviousHistory`, which moves within a multi-line draft and only
     walks history when there is no line above; the typeahead editor always
     walks. It is **reachable**, because a bracketed paste submits a multi-line
     draft as one entry and rustyline escapes the newline into the file. The
     author deliberately wrote **no** failing test — the inline viewport is **one
     row** and cannot display a multi-line draft at all — and pinned the
     boundary in a doc comment so nobody extends the walk by one ↑ and gets a
     false pass. Filed with the bordered palette under **F16**/**F19** as
     height-and-placement, not history. The mechanism was read; whether a real
     user's file contains such an entry is labelled a **hypothesis**.

- **A second occurrence of F39, and both times our own tooling destroyed the
  evidence.** The first `--test tui` run of the session reported **18 passed, 1
  failed**; four consecutive re-runs were 19/19. The agent **reported it rather
  than burying it** and saved output on every later run — but the name was
  already gone, because that run had been piped through `tail -4`.

  Two occurrences, two different suites, and in both cases the evidence was
  destroyed by how we were looking at it: once by **re-running** (my mistake, in
  F39), once by **truncating** (here). That is the same family as this project's
  standing rule never to assert absence from a `head`-truncated search — the
  habit that makes output readable is the habit that discards the part that
  matters. The rule now has two data points: **write the full output to a file
  first and read the file**; never pipe the only copy through `head`, `tail` or
  `grep`. Both unidentified failures would have been diagnosable under it.
