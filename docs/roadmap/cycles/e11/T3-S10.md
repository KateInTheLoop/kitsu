- **The card inverted its own premise, and mine.** I briefed it expecting a
  documentation exercise: the ~412 direct writers bypass the surface seam, so
  they are missing from the cell ring, and the plan asked for a "documented
  limitation list". That held — but the severe gap was somewhere else entirely.

  **`InlineSurface::write_block` goes *through* the seam and fed the ring
  nothing.** It **overrides** a trait default that would have forwarded each
  line to the fed path, and it is the path the **streamed assistant reply**
  travels, along with every `! error:` notice. So the ring — which N4 calls
  "the sole source for the transcript overlay and the `[` dump" — would have
  held **every tool line and no assistant text.** The exact inverse of the gap
  anyone was looking for.

  I verified each link myself: the override's body, the default's forwarding
  loop, and the three production call sites. The fix is one site, inside the lock
  already held, after the write and flush.

- **The census is answered, and answered better than a number.** 421 direct
  writer sites in `main.rs` — and the useful part is the triage: about **251**
  are chat-path output a user could expect in the overlay (`handle_slash` 114,
  `run_chat` 100, `handle_jobs_command` 37), while about **132** are on paths
  where **no viewport can exist at all**, so they can never be a gap.

  **The author declined to write a count assertion and argued it rather than
  skipping it:** a `== 421` test fails on every new diagnostic, which is noise
  rather than protection, and it would make the 132 irrelevant sites
  indistinguishable from the 251 that matter. *"The defensible number belongs in
  the docs; the defensible test is the one that pins the mechanism."* That is
  the right instinct, and the opposite of this project's usual answer — worth
  noting, because "add a test" is not always the answer.

- **F17's stale caveat is discharged, and replaced with the live one.** F17 said
  its reassuring measurement was taken in cooked mode and *"the harness must be
  re-run after the input path lands"*. **It was re-run, and the finding did not
  know for seven cards** — the test is titled "the staircase question, re-asked
  for raw input mode", and the mechanism is that `RawStdinGuard::engage` clears
  only `c_lflag` and **leaves `c_oflag` alone**, so `ONLCR` still supplies the
  carriage return the direct writers omit. Every `tcsetattr` in the workspace
  was checked to preserve that.

  The condition that **is** still live is sharper: the answer depends on nothing
  ever entering **crossterm's** raw mode, which *does* clear `OPOST`. One
  function does exactly that and has no caller in the binary. **The day someone
  wires it in, the staircase question reopens for all 421 sites** — and that is
  also the day N5's title and alt-screen clauses stop being vacuous. Both arrive
  with T5, together.

- **The partial-line decision, made and justified rather than guessed.** A block
  ending without a newline is **retained as a short ring line**, not held back.
  The reasoning is sound and I accept it: the ring is the sole record, so holding
  a partial back means text already on the terminal is absent from the overlay,
  and a final partial never terminated would be **lost permanently** — exactly
  **F47**'s shape. Retaining it short can split one logical line in two:
  visible, recoverable, never lost. Holding back would also need new cross-call
  state with its own unpinned semantics, and it is the option that *can* lose
  text.

- **F39's third occurrence, and the first with a name and a shape.** The
  implementer hit
  `test_scripted_and_jsonl_runs_are_byte_identical_under_the_default` failing
  once in a workspace run, with one side producing only `"FOREGROUND_DONE\n"`
  instead of the full transcript — a **join-timing** difference, not a
  byte-content one.

  **It handled it correctly, which is why a diagnosis exists:** it did not re-run
  to make it pass. It verified the test passes standalone, verified a workspace
  run with its change **stashed** also passed, and reasoned that the code it
  touched is reachable only from tests so cannot influence the CLI harness.
  Recorded with the observation that all three occurrences are in suites driving
  real child processes and waiting on asynchronous completion — the earlier two
  may be this same shape wearing different names. The fix is in the test: wait
  on the background agent's completion rather than the foreground's done-marker.
