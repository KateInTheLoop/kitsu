# E11 / F120 — a dropped tool result now says so

- **UTC start/end:** 2026-10-16T13:05Z / 2026-10-16T07:45Z
- **Branch/base:** `features/tui_herdr_improvements` / `c4fc1b9`
- **Epic/story/card:** E11 / **F120**. Records **F121**, **F123**; opens **F122**.
  **N1 clarified.** **My brief was wrong twice and both agents corrected it.**

- **The defect.** When the context budget forced history trimming to replace a
  whole tool result with `[older tool output elided]`, the result vanished before
  the provider saw it and **every JSONL event still reported success** — the
  tool's own receipt was honest and the turn's was not.

- **Two wrong hypotheses of mine, both refuted by measurement.** First: *"no event
  reports the loss."* Wrong — `CompactionOutcome::ToolResultsElided`, a named
  outcome and a dedicated count already existed. Refined to: *"the vocabulary
  exists but did not fire on this path."* **Also wrong** — a file-backed probe
  (deliberately not stderr, which the target test asserts empty) showed both
  elision sites set the outcome and a real `CompactionRecord` reaches the ledger.

  **The actual defect was the absence of a transport**, verified three ways:
  `compaction_report_payload` has **one** call site (`/compact`);
  `orchestrator.rs` **discards** the returned `CompactionReport` unbound; and
  `AgentRuntimeEvent` had **no compaction variant**, enumerated over the whole
  enum rather than searched. **The loss was detected, named, counted and recorded
  — and reached only two surfaces, both user-initiated after the fact.**

- **The catch that reshaped the fix.** The existing count **cannot** be reused: a
  low `--offload-cap` elision keeps a recallable pointer — the documented *good*
  case the flag exists to produce — and is **still counted**. So *"emit when
  `tool_results_elided > 0`"* would warn on the good case and become noise. A
  **second counter** splits lossy from lossless on `OFFLOAD_POINTER_PREFIX`, and
  the mutation proves it: emitting on the old count makes the **lossless** guard
  fail, splicing the event in after `tool_finished`.

- **N1 clarified, after I misread it as a blanket ban.** It lists four surfaces and
  **an interactive TTY run is not among them**; and for those four it constrains
  **the bytes of today's shapes, not the set of shapes.** A new additive `"type"`,
  emitted only on a path that is currently wrong, leaves every existing event
  byte-identical. The limit is stated honestly in the design doc: a consumer
  asserting *"exactly these types appear"* is affected, and that is accepted — **a
  run that drops a tool result and reports success is not a shape N1 was written
  to protect.**

- **Tests pin the provider's view, not the event stream.** The lossy test asserts
  the second request's content **is** the elision stub *before* looking for the
  event, so a fixture that stops losing anything fails on **the loss**, not on a
  missing report. The lossless test requires the pointer **and** the absent
  preview, so its silence cannot be vacuous. Two negatives pin the **full ordered
  event sequence** plus a raw-byte check.

- **The test author declined my instrument and was right.** My brief said to
  reproduce the loss by inflating a production tool schema. **A test depending on
  a production schema would be a new F117 tripwire** — the defect this epic spent
  two cards fixing. They used `--context-window`, measured the thresholds
  (8192/6144/4096 pass whole; **2048** drops; **1536 + `--offload-cap 1024`** is
  lossless), and fenced both numbers with provider-side assertions so drift fails
  loudly.

- **F123: my gate list omitted the crate the change lived in.** `kitsu-core` was
  never in the baseline list I have pasted into a dozen briefs — and
  `trim_tool_results_preserves_offload_pointer_but_drops_preview`, the test
  *directly* about this behaviour, compiles into `kitsu-core --lib`, **not** into
  `kitsu --bins`. The implementer ran it unasked: **160 passed**, both profiles,
  verified independently. The list had been assembled from the crates a **TUI**
  epic touched and then reused as if it were the workspace.
