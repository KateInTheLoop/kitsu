# Improvement Cycle 033

- UTC start/end: `2026-08-19T19:28:00Z` / `2026-08-19T20:27:00Z`

- Epic/story/card: E04 / E04-S02 / E04-S02-C2
- Requirement: derive the opaque profile portion of the route contract from a
  stable config namespace plus gateway key, with bounded collision-resistant
  framing and no endpoint/model/auth/flavor input. Make current composition
  retain a declaration for the compiled adapter, wire revision, and exact
  capabilities it actually constructs. The accepted `anthropic` label must not
  claim native Messages behavior. Do not publish a generation, alter a send,
  or expose the declaration as a receipt in this card.
- Evidence and expected failure: the new provider integration test first
  failed with `E0432`/`E0599` because `ProviderRouteDeclaration`, profile
  derivation, bounds, and errors did not exist. The first implemented stable
  vector then failed against its zero placeholder; an independent `sha256sum`
  over the documented domain/length-framed bytes produced the same full digest
  as the implementation before the truncated expected vector was accepted.
- In scope: domain-separated SHA-256 truncated to the v1 128-bit profile shape;
  64 KiB namespace and 1 KiB gateway-key bounds; canonical non-lossy config
  path encoding; declaration validation; exact current compatible-Chat
  streaming/tools/structured-output/usage/catalog capabilities; retained
  private `ChatSetup` declaration; all current flavor labels. Out of scope:
  live generation publication/replacement, endpoint/model/auth snapshot
  ownership, send admission/migration, attempt receipts, config schema changes,
  native Messages, provider account data, or user-visible output.
- Authority/failure/version/rollback notes: derivation is offline and reads no
  config content, environment, credential, endpoint, model, or response. Empty
  and oversized identity inputs fail before provider construction with
  length-only errors. Canonical path aliases share identity; gateway keys and
  config namespaces remain distinct. The newly direct `ring` dependency was
  already transitively locked through the HTTP stack, so this card adds no new
  package or network acquisition. Source revert is complete rollback.
- Tests added or changed: three provider declaration/derivation cases pin the
  independent exact vector, domain/length separation, input bounds, current
  capability set, catalog conditional, and direct adapter/wire mismatch. Two
  main tests prove `openai`/`anthropic`/`ollama` all declare compatible Chat,
  mutable route contents never affect profile identity, different keys do, and
  symlink aliases resolve to one canonical config namespace.
- Implementation: `ProviderProfileId::derive_v1` incrementally hashes bounded
  framed inputs with SHA-256 and encodes the first 128 bits. A validated
  `ProviderRouteDeclaration` separates pre-publication truth from a live
  `ProviderRouteIdentity`; the latter can be constructed from a declaration.
  `build_setup` derives and privately retains today's compatible-Chat
  declaration before constructing its inference/catalog providers.
- Review findings and fixes: review added canonical-symlink and mutable-content
  identity cuts, plus direct declaration mismatch coverage. Model catalog is
  advertised only for the same non-empty `models_path` condition used by
  provider construction. `Usage` explicitly means decoder normalization, not a
  promise that every compatible endpoint reports it. A source scan finds no
  flavor-to-adapter switch and core still imports no route types.
