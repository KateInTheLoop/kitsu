# Improvement Cycle 036

- UTC start/end: `2026-08-19T21:40:10Z` / `2026-08-19T21:58:21Z`

- Epic/story/card: E04 / E04-S03 / E04-S03-C3
- Requirement: make model identity part of every immutable logical-operation
  binding. A changed process-default model must publish exactly one successor
  before live session state changes; the same model is a no-op; failed
  publication must leave the old route usable. Foreground and child runs must
  retain one binding across all rounds, while explicit subagent profile models
  remain supported without changing the process default.
- Evidence and expected failure: two new provider tests first failed because
  model mismatch, scoped binding, and model replacement APIs did not exist.
  Production review then found two hidden consumers: saved-session resume also
  changes the live model, and subagent tools are constructed before `/model`
  while profiles may select a distinct model. A naive global equality check
  would have broken profiles or allowed background rounds to cross generations.
- In scope: bounded scoped-model handles; request-model zero-send validation;
  exact default-model successor/no-op publication; direct and resumed session
  publication; one provider binder resolution per foreground/subagent logical
  run after effective profile/model selection; safe mismatch diagnostics. Out
  of scope: endpoint/wire/auth config reload, management-only doctor/top-level
  catalog binding, attempt receipts, native Messages, or E05 picker UX.
- Authority/failure/version/rollback notes: model binding and publication are
  local and perform no provider/filesystem/process effect. Target validation
  precedes the write lock; stale/oversized/mismatch failure is value-free and
  leaves the current snapshot installed. The successor reuses unchanged frozen
  runtime/auth/policy owners. An admitted old request drains; a later round on
  its retained old handle fails stale before send. No persisted or wire schema
  changes; reverting binder/publication wiring restores Cycle 035 behavior.
- Tests added or changed: the route-handle matrix grows from six to eight with
  request-model mismatch, scoped profile-model success, exact successor/no-op,
  stale old handle, and oversized-target retention. A CLI fixture forces
  production publication failure then proves the next turn sends the old model.
  The existing model-switch JSONL fixture proves old/new wire models, and the
  live subagent test now proves the binder resolves once after model selection.
- Implementation: handles carry a bounded operation model separate from the
  snapshot's process default. `replace_model` atomically publishes a successor
  or returns the current handle for a no-op. Primary turns bind from their
  `AgentConfig` once. `ProviderBinder` resolves a child handle after live model
  and optional profile overrides are known, then retains it for every child
  round. `/model` and both resume paths stage discovery, publish, then commit
  live model/window/provenance state.
- Review findings and fixes: review rejected a current-owner-per-request design
  because a multi-round background child could silently cross generations.
  The per-run binder preserves explicit profile models and turns replacement
  into stale zero-send on the next old round. Review also added saved-session
  publication and moved failed-switch context discovery behind a pinned-window
  fixture so the production replacement failure itself is exercised.
