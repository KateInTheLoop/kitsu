- Requirement: verify the exact retained HEAD-to-root revision lineage without
  letting filesystem candidates, timestamps, directory order, or projections
  become canonical HEAD. Only exact parent links from the verified selected HEAD
  may participate. Traversal must be bounded, fully verified, mutation-free, and
  all-or-nothing.
- Evidence and expected failure: three requirements-first fixtures initially
  failed to compile because no lineage lookup existed. The first implementation
  passed selected-parent, orphan, missing-parent, and cycle cases. Review then
  added a self-consistent parent rewrite; it incorrectly returned `Present`,
  proving that parent revision identity alone did not bind retained bytes.
- In scope: exact parent-manifest digest binding; physical schema versioning;
  pre-install parent verification; CAS parent-digest recheck; compact verified
  revision links; bounded HEAD-to-root traversal; missing, retarget, cycle,
  limit, and orphan fixtures. Out of scope: recovery selection/publication,
  quarantine, projection rebuild, production mounting, branch/fork/export,
  alternate store conformance, and X005 promotion.
- Authority/failure/version/rollback notes: lineage reads grant no provider,
  credential, tool, filesystem mutation, command, approval, or child authority.
  Physical schema revision 2 adds required successor `parent_manifest_sha256`;
  root records require no parent digest. Revision-1 private stores are explicitly
  unsupported rather than decoded as revision 2. Neither schema has a production
  caller, and current-v1 files remain exact rollback.
- Tests added or changed:
  - a selected B→A chain returns `Present(B)` plus exactly `[B, A]` and matching
    parent/manifest digests;
  - an installed C candidate is ignored because HEAD still selects B;
  - missing A returns `MissingReference`, no partial lineage, and unchanged B;
  - a self-consistent rewrite of A's manifest and canonical bytes returns
    `DigestMismatch` because B binds the original manifest;
  - a one-revision test budget fails closed before following B→A;
  - an unrooted A→B cycle cannot allocate its first candidate because B is not a
    verified installed parent;
  - physical fixed vectors cover schema revision 2, root/successor digest shape,
    and exact parent digest capture.
- Implementation: advance the private physical schema to revision 2. Candidate
  install opens and verifies an exact parent before allocation, records its
  manifest SHA-256, and CAS compares that value with the admitted current HEAD.
  Canonical candidate verification now returns compact physical binding facts.
  The lineage lookup walks at most 4,096 exact links, verifies every canonical
  value and artifact closure, keeps a seen set, and publishes a lineage result
  only after reaching a digest-bound root.
- Review findings and fixes: review rejected revision-ID-only lineage after the
