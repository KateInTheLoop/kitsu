# Improvement Cycle 039

- UTC start/end: `2026-08-20T04:05:30Z` / `2026-08-20T04:10:56Z`
- Branch/base: `improvements/harness-roadmap` / `c021e37`
- Epic/story/card: E04 / E04-S04 / E04-S04-C1
- Requirement: compile one genuinely distinct native Anthropic Messages
  2023-06-01 adapter that matches the pinned text request and streaming event
  fixture, normalizes text/usage/terminal semantics through the neutral
  provider port, and remains unreachable from live composition.
- Evidence and expected failure: the primary Messages request/event fixture
  existed, but the only compiled adapter was compatible Chat and deliberately
  failed that fixture. The new integration tests initially failed to compile
  because `kitsu_providers::anthropic_messages` did not exist.
- In scope: exact `/v1/messages` request body; fixed `anthropic-version`;
  separate system field; streamed `message_start`, text delta,
  `message_delta`, usage, and `message_stop`; explicit EOF failure; bounded
  error/event bodies; pre-send refusal of unimplemented tools. Out of scope:
  tool-use/result translation, retry/attempt telemetry, catalog, immutable
  route factory, flavor selection, non-streaming responses, structured output,
  prompt-cache hints, and live credentials.
- Authority/failure/version/rollback notes: composition continues selecting
  only compatible Chat, so no production authority or configuration surface
  changes. The adapter accepts credentials only through the existing auth
  interface, fixes the wire version in compiled code, and fails unsupported
  request shapes before transport. EOF cannot synthesize `Done`; only an
  explicit valid `message_stop` can. Source revert removes the module and
  three fixture cases without a persisted/config/schema migration.
- Tests added or changed: an exact offline mock proves request body, version
  header, text, usage totals, and terminal reason; a truncated stream proves
  EOF yields an error and no terminal success; an expected-zero mock proves a
  tool-bearing request returns `ToolsNotSupported` before any send.
- Implementation: `AnthropicMessagesProvider` owns its request translation,
  bounded HTTP error reader, incremental bounded SSE decoder, and provider-port
  implementation. It supports only the truthful text capability slice and
  exposes no route builder or CLI selection.
- Review findings and fixes: the first test used `expect_err` on a boxed stream
  whose success type is not `Debug`; review replaced it with an explicit
  result match. The accepted decoder requires start-before-delta ordering,
  rejects duplicate starts/unknown event or stop reasons, checks usage
  overflow, emits usage before `Done`, and drops the body once explicit
  terminal truth is decoded.
- Acceptance commands/results:
  - `cargo test -p kitsu-providers --test provider_wire_matrix native_messages_`
    passed four matching cases including the pre-existing future tool bound;
  - `cargo test -p kitsu-providers --all-targets` passed 113 unit, six route
    contract, three declaration, twelve handle, four snapshot, and nineteen
    wire-matrix tests;
  - provider Clippy with warnings denied, workspace/all-target check,
    formatting, diff, roadmap receipt, run-boundary, production-selection, and
    original dirty-main preservation checks pass before commit.
- Commit: this cycle's focused `feat(provider)` commit.
