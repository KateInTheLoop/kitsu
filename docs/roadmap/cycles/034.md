# Improvement Cycle 034

- UTC start/end: `2026-08-19T20:28:00Z` / `2026-08-19T21:08:07Z`
- Branch/base: `improvements/harness-roadmap` / `c26fac4`
- Epic/story/card: E04 / E04-S03 / E04-S03-C1
- Requirement: consume the truthful route declaration into one initial
  immutable runtime snapshot before migrating physical send admission. The
  snapshot must own generation one, a bounded model, exact auth source class,
  retry/catalog/time policy, and both compatible-Chat runtimes constructed from
  one endpoint/path input. Credentials must resolve once per generation so an
  environment mutation cannot alter a retry or auxiliary call. Do not expose
  endpoint or credential material, claim current-generation admission, or add
  replacement behavior in this card.
- Evidence and expected failure: the new provider integration fixture first
  failed with unresolved snapshot/policy/auth-source types and missing bounded
  validation errors. Source review then found that `EnvBearerAuth::header`
  reads process environment for every request, so a retry could change
  credentials without a route-generation change. The factory/source tests did
  not exist before this card.
- In scope: provider-neutral snapshot/policy/source values; nonempty 4 KiB model
  bound; nonzero inference/catalog/advisory time budgets; exact catalog-policy
  versus capability agreement; initial generation one; sensitive frozen auth
  backed by zeroizing bytes; one compatible-Chat factory; `ChatSetup`
  composition migration; exact whitespace-managed fallback source. Out of
  scope: a current-generation publisher/handle, send-time stale admission,
  same-label replacement, replay/title/compaction binding, drain/cancel policy,
  user-visible receipts, native Messages, or config schema changes.
- Authority/failure/version/rollback notes: construction performs no network or
  filesystem authority expansion. Auth resolves through the existing validated
  provider before the snapshot is returned; missing/malformed auth keeps the
  existing typed safe error. The snapshot is neither `Debug` nor serializable;
  its auth source has no variable/header/token/fingerprint, and sensitive
  header bytes zeroize on drop. Empty/oversized models, zero budgets, and
  catalog mismatch fail before publication with bounded value-free errors.
  Source revert restoring the two constructors is complete rollback.
- Tests added or changed: three provider snapshot cases cover coherent initial
  ownership, bounds, time budgets, and both directions of catalog mismatch;
  two auth cases prove frozen environment credentials remain sensitive and
  immutable plus explicit no-auth; one adapter-factory case proves shared
  endpoint/path/auth with distinct frozen retry/time budgets; one CLI case
  proves environment/managed/static/none source selection including whitespace
  fallback.
- Implementation: `ProviderRouteSnapshot<P>` owns the secret-free route facts
  and `Arc` runtimes; `ProviderRoutePolicy` owns retry/catalog/time choices;
  `FrozenAuth` copies one already validated sensitive header into zeroizing
  storage. `build_openai_compatible_route` consumes one configuration, shares
  the frozen auth object, and constructs the inference plus catalog providers.
  `build_setup` retains the snapshot and gives existing call sites clones of
  its owned runtimes.
- Review findings and fixes: review corrected bearer source reporting for
