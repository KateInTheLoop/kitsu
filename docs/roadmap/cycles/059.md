- Requirement: turn the accepted physical-v1 layout into a private,
  descriptor-pinned store/candidate adapter that never clobbers an existing
  identity or revision and verifies the exact bytes that a future HEAD may
  select.
- Evidence and expected failure: isolated filesystem fixtures were added first;
  the focused Kitsu target failed to compile because `PhysicalFileStoreV1` and
  its create/open/install/read operations did not exist.
- In scope: exact store-ID create/reopen, bounded record/payload reads, synced
  create-new files, private staging, atomic directory no-replace installation,
  exact canonical and manifest SHA-256 verification, physical identity binding,
  joined pre-install cleanup, and installed-unconfirmed post-rename truth. Out
  of scope: HEAD reads/CAS, writer-fence integration, production mounting,
  current-v1 migration, recovery, branch-at-turn, and X005.
- Authority/failure/version/rollback notes: the helper consumes only Kitsu-owned
  inert typed IDs and canonical bytes. It opens path components without
  following symlinks on Unix and grants no model/provider/tool authority. Linux/
  Android `RENAME_NOREPLACE` and Apple `RENAME_EXCL` are the only compiled atomic
  directory-install paths; unsupported platforms fail closed. No production
  caller exists, so source revert removes the isolated namespace implementation
  without a data migration.
- Tests added or changed:
  - create/reopen preserves exact `store.json`; a different or corrupt store ID/
    schema fails without rewriting it;
  - candidate round-trip verifies exact manifest bytes, manifest digest,
    canonical length/digest, physical identity, and empty staging residue;
  - revision collision preserves the first exact payload and removes the losing
    staged tree;
  - payload tampering, manifest retargeting, and symlinked canonical content fail
    closed;
  - an injected target-parent sync failure reports installed-unconfirmed and the
    installed candidate remains exactly verifiable.
- Implementation: add `PhysicalFileStoreV1` with pinned root/revision/staging/
  HEAD/lock handles, idempotent no-clobber store initialization, bounded regular-
  file readers, synced create-new writers, staged manifest/payload construction,
  platform-gated no-replace directory rename, typed install error truth, rollback
  cleanup, and verified candidate receipts.
- Review findings and fixes: canonical fixtures initially used raw byte strings
  containing a literal `\\n`; review changed them to valid newline-terminated JSON
  bytes. Store corruption now has its own no-rewrite regression. Candidate
  installation syncs both rename parents, distinguishes pre-install from
  installed-unconfirmed failure, and truthfully refuses platforms without an
  atomic no-replace primitive.
