- Epic/story/card: E03 / E03-S04 / E03-S04-C1
- Requirement: derive a deterministic read-only last-good recovery plan from
  the selected revision's exact digest-bound physical ancestry. A plan may cross
  corrupt logical revisions but may select only a fully verified canonical value
  and artifact closure. It must not publish, mutate, implicitly fall back, hide
  ordinary lookup failure, or restore provider/tool/filesystem authority.
- Evidence and expected failure: three requirements-first fixtures failed to
  compile with missing `CanonicalRecoveryPlanV1` and
  `plan_last_good_recovery`, proving there was no recovery decision surface. The
  first implementation passed those fixtures; review added a corrupt-parent /
  verified-grandparent case to prove traversal rather than one-parent special
  casing.
- In scope: explicit missing/already-valid/available/unavailable outcomes;
  selected corruption truth; exact parent revision and manifest-digest
  traversal; repeated corrupt ancestors; fully verified recovery HEAD; bounded
  cycle/limit refusal inherited from the 4,096-revision policy; future selected
  schema refusal; physical and ordinary-lookup immutability. Out of scope:
  selected physical-envelope/payload corruption, recovery publication,
  quarantine, user confirmation, production mounting, branch/fork/export,
  alternate store conformance, and X005 promotion.
- Authority/failure/version/rollback notes: planning performs descriptor-pinned
  reads only. It grants no credential, provider, tool, filesystem mutation,
  command, approval, child, or remembered session authority. Unsupported
  selected logical or physical schemas remain unavailable and cannot trigger an
  older revision. Current-v1 production files remain the exact rollback and no
  canonical HEAD is rewritten.
- Tests added or changed:
  - absent HEAD returns `Missing`; a verified selected revision returns
    `NotNeeded` with its exact logical HEAD;
  - corrupt selected B identifies verified parent A while raw HEAD and ordinary
    lookup remain B and corrupt before and after planning;
  - corrupt selected C crosses corrupt parent B and returns only verified
    grandparent A through both bound manifest digests;
  - corrupt root B reports `Unavailable` and leaves it selected;
  - future logical selected B reports `Unavailable(Unsupported)` and never
    downgrades to valid A;
  - the existing nine-case physical HEAD/revision fault table now also proves
    recovery planning preserves each typed selected state and stays unavailable.
- Implementation: add a private recovery-plan value beside canonical lookup.
  Read the selected verified physical candidate once, decode it normally, and
  return `NotNeeded` on complete validity. For current corruption only, follow
  exact parent identities and compare every parent manifest SHA-256 before
  decoding its complete canonical/artifact closure. Return the first verified
  ancestor or `Unavailable`; retain a seen set and the shared hard bound. The
  method owns no publication primitive and never calls HEAD CAS.
- Review findings and fixes: review expanded the initial one-parent proof to two
  corrupt generations, asserted the `NotNeeded` logical HEAD rather than only
  revision identity, exercised true missing state, and repeated ordinary lookup
  after planning. It also kept future selected schema as an explicit no-downgrade
  gate. No scan, directory-order choice, orphan promotion, or partial payload is
  exposed.
