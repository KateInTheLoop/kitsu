  transaction API could only acquire a new writer fence, which conflicts with
  the fence already retained by canonical activation.
- In scope: exact canonical base retention; pure successor/projection staging;
  held-fence identity validation; exact logical-base revalidation; parent-
  envelope candidate binding and CAS; confirmed/unconfirmed receipts; retained
  base/projection advancement after publication; typed current-v1 routing and
  artifact refusal. Out of scope: current-v1 snapshot save implementation,
  production `SessionStore` routing, artifact-aware resume, migration, provider

- Authority/failure/version/rollback notes: the fence is an exact store/session
  capability, not model authority. Wrong fences, stale HEAD, a different valid

  before allocation. Candidate-install cuts preserve the old HEAD and typed
  residue; post-HEAD sync cuts report the new visible revision as published but
  durability-unconfirmed. A not-published result leaves the activation's base
  and projection unchanged. Removing the private save method restores Cycle 087
  behavior without changing production routing or on-disk schema.

  published result replaces the activation's base/projection. The current-v1
