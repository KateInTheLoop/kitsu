# Improvement Cycle 051

- UTC start/end: `2026-08-20T06:04:00Z` / `2026-08-20T06:32:00Z`

- Epic/story/card: E03 / E03-S01 / E03-S01-C2
- Requirement: turn the accepted canonical-session ADR into a provider-free,
  store-neutral logical value contract before extracting or changing current
  persistence. Opaque identities, revision expectation, logical HEAD/history,
  typed lookup states, and commit receipts must be bounded, versioned, and
  impossible to reconstruct from physical store facts.
- Evidence and expected failure: the red integration fixture initially failed
  to compile because `kitsu-core` exposed none of the named session contract
  values. The existing production `SavedSession` remained the only concrete
  shape and therefore could not express an opaque revision, selected HEAD,
  terminal-bound operation, corrupt/unsupported/conflict read, or publication
  receipt independently of the file adapter.
- In scope: typed store/session/revision/turn identities; missing/exact revision
  expectation; genesis/turn HEAD; immutable terminal outcome projection;
  validated canonical operations and histories; closed corrupt/schema/lookup
  states; not-published/published durability receipts; fixed JSON vectors;
  adversarial decoding; a CI dependency guard. Out of scope: a store trait,
  current-v1 wrapping, filesystem writes, migrations, projection rebuild,
  branch commands, second store, runtime plugins, or X005 promotion.
- Authority/failure/version/rollback notes: IDs accept only bounded machine-safe
  opaque text and provide no lexical ordering. Only committed assistant
  dispositions advance HEAD; discarded/absent outcomes retain it. Contract
  revision 1 is explicit at each persisted aggregate and future/unknown values
  fail closed. Receipts report publication/durability, never semantic success.
  The module imports no store, config, credential, permission, provider, tool,
  process, Tokio, filesystem, or presentation owner. Revert removes an unwired
  value module, tests, CI guard, and docs; production session bytes are unchanged.
- Tests added or changed:
  - six `session_contract` cases cover bounded identities, terminal-driven HEAD
    advance/retention, one exact history vector, ancestry and duplicate
    rejection, all five lookup states, CAS conflict validation, and separate
    publication receipts;
  - adversarial mutations reject future contract revisions at history/state/
    outcome/receipt levels, unknown physical-path fields, malformed committed
    operation heads, unsafe IDs, overlong history, matching conflicts, and
    no-op revisions;
  - the new boundary script passes on `kitsu-core::session` and rejects an
    alternate concrete orchestration source as its negative fixture.
- Implementation: add `kitsu-core::session` and re-export its neutral types.
  Constructors validate invariants before construction; custom deserializers
  route decoded values back through those constructors. Add
  `scripts/check-session-boundary.sh` to CI so the logical contract may use
  Serde for its own closed wire shape but cannot acquire physical/runtime
  dependencies.
- Review findings and fixes: the initial state/outcome envelopes lacked their
  own contract revision even though nested history/receipts were versioned;
  review added explicit top-level revisions and future-version refusals. A
  duplicate-turn fixture could stop first at head discontinuity, so a distinct
  valid-head fixture now proves duplicate run rejection directly. Deserialized
  operations now prove constructor invariants cannot be bypassed. A needlessly
  nested diagnostic match was simplified before Clippy. Final review also found
  that requiring selected HEAD to equal the final operation would make the file
  tail authoritative and prevent rollback; history now accepts Genesis or any
  validated committed ancestor while refusing unknown or failed-turn parents.
