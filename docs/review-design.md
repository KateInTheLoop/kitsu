- **P1** — Token read per-request from env, but `refresh-token` refreshes the login shell, not the running process (your own gotcha). Long `chat` sessions will silently use a stale token until 401. Add a re-read-from-source or file-based token option. *(functionality.md gotchas)*
- **P1** — Warn-but-send on expiry is defensible (clock skew), but there's no rate limit on the warning and no distinction between "5s expired" and "3 days expired." Suppress/escalate based on magnitude. *(architecture §3)*
- **P2** — JWT `exp` fallback decodes unsigned base64 — fine since never trusted, but ensure malformed middle segment → `Unknown`, never panic. Test covers UUID case; add garbage-base64 case. *(architecture §3, §7)*

## (3) Agent tool-loop design

- **P1** — Context-budget truncation drops oldest *tool-result* messages but keeps their corresponding `assistant` tool_call messages. OpenAI-compat API rejects a `tool_calls` assistant message with no matching `tool` response → 400. Truncate the pair atomically. *(architecture §5 context growth)*
- **P1** — `max_rounds` appends `[stopped: ...]` but returns it as the answer; the model never gets to summarize. For a coding agent this silently truncates work. Consider one final no-tools round. *(architecture §5 cond. 2)*
- **P2** — Error-as-tool-result has no loop-breaker: a model that keeps retrying the same denied path burns all 10 rounds. Track repeated identical failures and short-circuit. *(architecture §5)*
- **P2** — Streaming `tool_calls` are incremental "by index"; partial/interleaved deltas across choices are a known OpenAI-compat footgun. Ensure the collector tests cover fragmented argument JSON, not just two clean fragments. *(architecture §4, §7 test)*
