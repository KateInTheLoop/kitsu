# Cutting a release

Releases are driven entirely by tags. Pushing `vX.Y.Z` builds every artifact and
publishes the GitHub Release; nothing else needs to happen by hand.

## Steps

1. Bump the version in the workspace manifest:

   ```bash
   sed -i 's/^version = ".*"/version = "0.2.0"/' Cargo.toml
   cargo check            # refreshes Cargo.lock with the new version
   git commit -am "release: 0.2.0" && git push
   ```

   The tag and `[workspace.package] version` must agree — the `verify` job
   fails the run in seconds if they don't, before any build starts.

2. Tag and push:

   ```bash
   git tag v0.2.0
   git push origin v0.2.0
   ```

3. Watch it: `gh run watch` (or the Actions tab). ~10-15 minutes for a cold
   cache. The release appears with autogenerated notes from the commits since
   the previous tag.

A tag containing a hyphen (`v0.2.0-rc.1`) is published as a pre-release.

## What gets built

| Platform | Artifacts |
| --- | --- |
| Linux x86_64 | `.tar.gz`, `.deb`, `.rpm` (static musl) |
| Linux aarch64 | `.tar.gz`, `.deb`, `.rpm` (static musl) |
| macOS | `.tar.gz` for aarch64, x86_64, and universal2 |
| Windows x86_64 | `.zip` |

Plus a `SHA256SUMS` covering every asset.

The Linux binaries link musl statically, which is why the `.deb` declares no
dependencies and the `.rpm` disables auto-requires: the packages install on any
distro of that architecture regardless of its glibc, including releases older
than the CI runner. Package metadata lives in `[package.metadata.deb]` and
`[package.metadata.generate-rpm]` in `crates/kitsu/Cargo.toml`.

## Dry runs

Run the **Release** workflow manually from the Actions tab (`workflow_dispatch`).
It performs every build and packaging step and attaches the results to the run
as workflow artifacts, but the publish job is skipped because the ref is not a
tag. Use this after touching the workflow, so a broken pipeline is never
discovered mid-release.

## Signing

macOS binaries are unsigned and unnotarized; users clear the quarantine bit on
first run. Signing needs an Apple Developer ID certificate in the repo secrets
plus a `codesign`/`notarytool` step in the `macos` job.
